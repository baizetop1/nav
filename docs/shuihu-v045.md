# 白泽水浒 0.45.0：人物本领与出征搭配

本轮补全“不同人物值得换上场”的一段玩法。独立人物本领从六人扩充到十二人；既有招式、兵种、天赋、路线契约继续生效。未改招贤或坐骑掉落概率，不新增强制日常，也未开发 APK。

## 新增六人本领

| 人物 | 本领 | 实际条件和效果 |
| --- | --- | --- |
| 宋江 | 济困振心 | 招式实际恢复气血后，受疗者额外增加最多 8 怒气，每 6 秒最多一次。满血或满怒不触发，不浪费本领冷却。 |
| 吴用 | 借隙谋攻 | 普攻处于削弱、破甲或眩晕中的敌人，伤害增加 12%；状态到期即失效，主动技能不叠加此效果。 |
| 鲁智深 | 危阵不退 | 受到直接伤害后仍存活且气血不高于 40%，获得 18% 护阵 5 秒，每战一次。仅减免后续伤害，不抵挡触发本领的那一下，不复活，不由毒伤触发。 |
| 花荣 | 先声夺阵 | 普攻气血不低于 75% 的目标，伤害增加 12%；主动技能不享受此项加成。 |
| 武松 | 独敌决胜 | 敌方只剩一人在阵时，普攻伤害增加 12%。有随从时先清场才满足条件。 |
| 阮小七 | 护舟接阵 | 水域战斗开场为存活同伴提供 10% 护阵 4 秒；非水域不触发，已退阵的本人不能为队友提供本领。 |

这些本领随正式出阵生效，无额外解锁费用；剧情助阵和教学演武不借用。护阵沿用已有合并规则：取较强比例和较晚到期时间，不将比例相加。比如林冲排首位时，与阮小七同队仍为 12% 护阵，而不是 22%。

治疗回怒、护阵和增伤都会进入真实战斗；战后复盘保留本领触发次数。治疗回怒只来自实际招式治疗，药品不算。

## 如何体验

1. 在寨子“山寨出征”或其他已有出征准备入口选择战斗。
2. 打开新增“搭配”页，与“概览 / 配置 / 敌情”并列。
3. 查看当前三人的本领、站位提示、地形适用性，以及已解锁招式能否配合。
4. 在“配置”换人后点击“更新出征预览”，搭配建议随本次方案变化；取消保留原阵容，不扣资源。
5. 确认出征，胜利或撤退结算后在复盘查看触发记录。

可尝试：花荣先压低高血目标，时迁收割半血目标；武松先配合清掉随从再处理首领；鲁智深低血护阵时用治疗接住后续伤害；吴用配合实际已解锁的控制或破甲招式。建议只显示实际出阵人物，不自动换队，也不承诺必胜。

手机保持紧凑页签、固定底部确认 / 取消按钮。长内容沿用现有分页，不新增纵向长滚动。320×568 下实际双人搭配页和操作按钮可在一屏内完整显示；较多建议按页查看。

## 存档和云服务

- 新开正式战斗使用人物本领规则版本 2；原规则版本 1 的在途战斗保持原效果，不在加载时补发新本领。
- 冷却、护阵和触发次数随战局保存；刷新不重发开场效果或重置每战一次的保护。
- 旧存档和旧复盘可正常导入。战报保存其实际使用的人物本领版本。
- Worker 新增能力字段 heroRoles: 2。上传新战局或战报前检查能力，旧服务会给出升级提示并保留本地进度。
- 服务端拒绝将已有新版战局或复盘降为旧版，避免旧客户端覆盖新记录。
- 不新增 D1 表，不需要 SQL 迁移。

## 发布顺序

本轮未提交、推送或部署。在 Git Bash 中逐行执行，遇到错误先停下：

```bash
cd /f/nav-main/nav-main
npm run test:all
npm run build
npx wrangler deploy --config cloud/shuihu/wrangler.json
curl https://save.baizeone.top/v1/game-version
```

确认 release 为 0.45.0、heroRoles 为 2 后再上传前端：

```bash
git status
git add public/game cloud/shuihu/worker.js package.json scripts/shuihu-lineup-selfcheck.mjs scripts/shuihu-lineup-cloud-selfcheck.mjs scripts/shuihu-lineup-browser.mjs scripts/shuihu-hero-roles-selfcheck.mjs scripts/shuihu-dialog-pages-selfcheck.mjs docs/shuihu-v045.md
git diff --cached --stat
git commit -m "feat: expand hero roles and add formation advice"
git pull --rebase --autostash origin main
git push origin main
```

上述暂存范围不包含本地 android/ 和 .gitignore。--autostash 会在同步前临时保存未提交的受跟踪修改，结束后尝试恢复；若出现冲突，保留提示并处理后继续，不要强制推送。
