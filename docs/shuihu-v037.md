# 白泽水浒 0.37.0 · 江湖游历

本次改动针对“玩过一次，不想再打开”：把旧短程远征的入口升级为一趟可保存、能形成不同打法的游历。寨子总览可直接开始或接续。仍在旧版远征中的存档先按旧规则走完，不丢失物资或路线。

## 游玩流程

- 聚义厅 2 级、队内至少一名 8 级英雄开放。三条路线：青石古道、芦荡渡口、断崖粮道；各有探路、险途、绝险，准入等级为 8 / 15 / 25，逐级走通开放。
- 出发先选练兵材料、英雄修习或营建补给；体力 16 / 20 / 24，启程粮草 15 + 实际兵力的三分之一向上取整。没有每日出发次数限制。
- 五段路线启程即生成并展示。每个节点前战法三选一，一趟至多五项；临时影响攻击、防御、气血、速度、初始怒气、治疗、粮耗和战利品。特定战法之间有额外搭配效果。
- 前四段可选择交锋、强敌、休整、采粮、护送、冒险搜索或采买；第五段为首领。战斗节点另扣粮草。气血与士兵损失连续保留，退阵英雄不会被休整复活。
- 选项和路线进入本机/文件/云端存档，刷新不重抽。离开页面可保存再继续；“结束本趟”则实际收队，带走暂存战利品一半，补给与阵亡不返还。
- 走通带回全部暂存战利品及所选目标物资。每条路线首次完成发现两项新战法（初始 8 项，完整 14 项），加入下一趟的随机候选。每路每个新难度首次通关另获材料自选匣 1。
- 每个游戏现有轮换周期（每月四期，非固定七天），前三次走通各获招贤令 1，三条路线共用。重复游历不能刷首通奖励；抽取概率不变。
- 战斗胜利立即获得本段经验；其余战利品暂存至收队，界面分开显示。通关收获弹窗展示新战法和难度解锁。

## 手机

复用全屏翻页，不增加纵向长列表。360 × 640 手机上，三项战法可在首屏同时阅读和选择；次要路线记录、已选战法放在后续页。默认路线正确展开，战后直接接着选择下一段。

## 存档与部署

- 浏览器静态资源版本为 0.37.0。没有构建或更新 APK。
- 需要部署新 Worker 才能上传游历进度：服务声明 `journeys: 1`，旧服务会被前端拦截，本机进度保留。
- 无需新增 D1 表或执行数据库迁移。游历记录保存在既有存档 JSON 中。
- Worker 拒绝旧客户端删除游历记录、降低已通关难度或回退同一期已领取招贤令数量；原有专门历史回滚接口仍保留。

在 Git Bash 的项目根目录中，先验证，再升级服务，最后发布前端：

```bash
cd /f/nav-main/nav-main
npm ci
npm run test:all
npm run build
npx wrangler deploy --config cloud/shuihu/wrangler.json
curl https://save.baizeone.top/v1/game-version
# 确认响应含 "journeys":1，且 release 为 0.37.0 后，再提交并推送前端。
git status
git add public/game cloud/shuihu package.json scripts docs
git diff --cached --stat
git commit -m "feat: add replayable journeys and temporary battle builds"
git pull --rebase origin main
git push origin main
```

如果尚未提交 0.35/0.36 的依赖文件，需要把相应新增模块和测试一并纳入提交；以 `git status` 为准。rebase 出现冲突时先解决再继续，不能强制推送。上述命令是部署说明，本次开发未执行线上部署或 Git 推送。

## 验证

- `npm run test:shuihu-journey`：真实战斗三路线、三级难度、临时战法、存档恢复、首通/周期奖励及异常输入。
- `npm run test:shuihu-journey-cloud`：实际 Worker 与内存 SQLite 的待选/交战/走通/领奖存档往返及降级保护。
- `npm run check:shuihu-journey`：手机与桌面的真实按钮完整游历、刷新接续和领奖流程，需要 Playwright 与本地开发服务。
- `npm run check:shuihu-screen-pages`：现有各页面手机适配与交互回归。
