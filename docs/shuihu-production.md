# 白泽水浒 0.19.0：生产收取与工坊订单

## 分开收取和加工

旧版“收取产出与加工”会收取原料并立即消耗木材、碎铁冶炼，可能用掉玩家准备升级建筑或练兵的材料。现在寨子 → 山寨生产提供两项独立操作：

- 预览收取产出：仅收取农田、伐木场及补给畅通据点的物资，不扣木材、碎铁，不改变工坊待加工额度。
- 工坊订单：选择 1、5、10 批或全部可加工数量。每批消耗木材 2、碎铁 2，产精铁 1，不耗碎银和体力；需预览并确认。

可加工数量取工坊额度、两类原料能支持的数量和精铁库存余量的最小值。选择数量过多时，预览先缩减到实际可加工数量，显示原料、成品和额度的前后变化。确认再次检查条件；取消不修改存档、不扣料。未使用额度保留。

库存上限仍为每项 10,000,000；同种物资来自多个产地时合并计算剩余空间，装不下的物资保留在对应产地。告急据点的暂存物资保持锁定，解围后才能收取。

## 预览时钟

生产预览使用只读的当前时刻进度副本，计入已完成的新批次；不提前写盘或入库。预览后额度或库存发生变化时，确认拒绝旧方案并提示重新预览，避免使用过期数量。演武传习预览同步使用当前时刻副本，避免跨日时反复引用昨日次数。

## 存档和发布

继续沿用既有生产库存、工坊 bank 和角色进度，没有新增存档字段或数据库表，无需数据库迁移。已有 0.18.0 未提交改动保留，当前原项目版本为 0.19.0。旧客户端仍保留旧版收取逻辑，多设备应刷新到当前页面版本。本轮没有推送 GitHub、部署云端或修改生产云档。

## 验证

新增 `npm run test:shuihu-production`，覆盖只收不加工、四种数量、资源不足、两类库存上限、告急据点、取消前状态不变、过期预览及新批次刷新后再确认、失败不扣费和导入导出。既有领地测试调整为先收取再单独加工，并继续验证真实据点战与离线生产。

全量自检与生产构建通过；隔离浏览器验证手机/桌面收取、取消、10 批缩减至 2 批、实际消耗与结算、缺料禁用、刷新和文件导出；没有使用个人浏览器存档或真实云端密钥。


## 挂机安排：寨中生产与通关地区派遣

新增入口：更多 → 寨务 → 挂机，或寨子功能切换 → 挂机安排。三个分页分别管理寨中生产、通关地区派遣和材料用途。旧生产库存、任职、升级和工坊加工继续保留；生产页可查看设施等级、批次收益、暂存材料，并进入任职、营建和加工。

安全派遣目前支持旧矿洞、芦苇泽、荒祠地宫，以及青石古道、芦荡渡口、断崖粮道。任一难度实际通关后解锁该地区，读取已有通关记录，老玩家无须重打。特殊副本与江湖游历页均提供派遣入口。

- 同时派一位空闲好汉。未通关、主队成员、任职人员、其他外派或远征中的人物不能派遣；派出后不能同时出阵、任职或培养，先接回再调整。
- 不带兵，不扣体力、粮草或碎银，不发生战斗和阵亡。原有每日一次的分队远征仍是有战损的委托，不属于安全挂机。
- 每 30 分钟产一批，最多暂存 16 批；离线最多按八小时计算。打开页面、重复刷新或重复领取不会额外生成材料。领取保留不足一批的计时；接回终止派遣，不足一批不结算。
- 地区决定基础产物：矿洞和断崖产碎铁/精铁，芦泽和渡口产药草/布匹，荒祠产布匹/草料，古道产皮革/药草。匹配任职专长时主要材料每批额外 +1；不依赖品质与等级。
- 领取后好汉继续采集；接回会尝试收取完整批次并立即释放人员。库存上限放不下的材料保留，即使接回也不丢失；收好暂存物资后才能再次派遣。
- 挂机产出基础材料和地区特产；特产可按地区配方制作成品，副本专属掉落仍需主动探索。

存档新增可选 idleDispatch 字段，旧存档继续兼容。发布时前端与 Worker 需同步更新，Worker 能力 idleDispatch:1；无需 D1 数据库迁移。旧服务无法接收新派遣记录时前端先拦截上传，本机仍可正常游玩与导出。云端拒绝丢失派遣记录或较旧收取进度的覆盖。

检查命令：npm run test:shuihu-idle、npm run test:shuihu-idle-cloud、npm run check:shuihu-idle。浏览器验证使用隔离存档，覆盖 320/390/1440 宽度下的入口、未通关提示、人员选择、派出、离线重新载入、领取、取消/确认接回，以及寨中原料生产和收取。


## 地区特产、采集点与回寨用途

每批在原有基础材料之外增加一份地区特产。特产不在商店出售，不改变特殊副本原有概率表、招贤概率或抽取保障。

| 地区 | 特产 | 地区配方成品 | 每日加工上限 |
| --- | --- | --- | --- |
| 旧矿洞 | 磁铁砂 | 守路长枪 ×1 | 2 |
| 芦苇泽 | 泽兰 | 金疮膏 ×1 | 3 |
| 荒祠地宫 | 旧碑拓片 | 武学残页 ×2 | 4 |
| 青石古道 | 山藤 | 斥候短褐 ×1 | 2 |
| 芦荡渡口 | 水韧苇丝 | 野营药包 ×1 | 2 |
| 断崖粮道 | 赤铜砂 | 稳步束带 ×1 | 2 |

地区配方在通关后开放，需对应集市或医馆 2 级，逐次消耗特产、常用材料和碎银。药品、残页与野营药包和普通加工共用每日次数，不能切换配方绕过限额；装备保留原有属性、穿戴、强化和分解规则。

- 本地区累计走通三次：发现对应矿脉、药圃、石室或采集地，特产由每批 1 份增至 2 份。母本与密室计入同一地区。
- 本地区通关第二难度：探明险路，主要基础材料每批再加 1。任职专长加成仍独立生效。
- 只在成功结算完整路线时记录；失败、提前返回、刷新、离线采集均不推进发现进度。发现前已经暂存的物资不会追补。
- 老存档特殊副本按现有通关次数补记。旧游历仅记录最高难度，按能确认的最少通关次数补记。首次新结算或安排派遣时写入记录，无需手动迁移。
- 派遣或生产领取后直接进入“材料用途”，优先列出库存齐备的地区配方与最多两名可练兵或升品的好汉，跳转时选中具体配方或人物。项目按当前库存分别判断，不代表能一次付清所有推荐。
- 行囊材料详情、挂机地区、特殊副本与游历路线均可查看采集点进度或进入对应配方；手机按既有分屏处理，不新增长列表。

新增可选存档字段 gathering（version:1，六地区的 runs/best，分别封顶 3），以及六种材料库存。Worker 增加 regionalGathering:1 能力并拒绝删除/倒退采集点的覆盖；旧 Worker 在上传前会被拦截，本机可继续玩并导出。部署顺序为先 Worker、后前端；不新增 D1 表，无需数据库迁移，APK 要随前端重新打包才含此玩法。

检查：npm run test:shuihu-gathering、npm run test:shuihu-gathering-cloud、npm run check:shuihu-gathering。覆盖真实六地区通关、发现/收益边界、失败与提前返回、采集领取、精确扣料、共用次数与每日重置、库存上限、旧档、Worker 往返及手机/桌面“领取→配方→制作→培养”操作。


## 区域探索、人物与回寨营建

本轮完整区域为旧矿洞（江湖 → 区域探索，也可从更多 → 探索进入）。地图与地点详情分开，六个地点及连接提前可见，位置与事件长期保留。其他地区暂沿用已有副本／游历，尚未复制这条人物事件链。

1. 运矿道可重复挑战，沿用特殊副本概率表，不耗体力、粮草，不派士兵。
2. 塌方石室击败守卫后救回矿工老杜，打开深层矿脉；亲自勘察后磁铁砂每批额外 +1，不追补旧暂存。
3. 旧炉房结识汤隆，交磁铁砂 3、精铁 2 修炉；普通矿道同难度累计五胜后可挑战矿头。取回工具后邀请汤隆，无需抽取；已入寨者仅完成事件，不重复发放人物／信物。
4. 击败矿头后货郎回到矿口，每天可用碎银 60 换精铁 3。藏室的强化符仅取一次。失败与撤退不推进区域事件。
5. 探索营建新增矿砂炉（磁铁砂＋赤铜砂，地区装备加工银耗 −20%）、配药间（泽兰＋水韧苇丝，地区药品每份少用药草 1）、客舍（山藤＋旧碑拓片，安置老杜后旧矿洞每批碎铁 +1）。各需相应材料各 6、营建木材 30、碎银 150，聚义厅 2 级；不替代或提高基础探索的建筑门槛。

挂机可手动开启“顺路寻访”。每累计八批采集（四小时）获得该地区人物信物 1，最多暂存 2；关闭时暂停进度，满额不补发，领取与材料共用入口。矿洞／芦苇泽／荒祠／古道／渡口／粮道分别对应汤隆／安道全／乐和／时迁／阮小七／项充。收到未结识者的信物仅记为听闻，不自动入寨；抽取概率与保底不变。主队和外派人手互斥规则保留。

新战场总览展示当前前后排、血量、状态、集火与随军人数。普通战斗胜负确定并成功写盘后自动结算，再显示“继续／查看战报”；两个按钮均不再发奖励。连续挑战沿用已有自动流程。磁盘写入失败明确提示尚未保存；标签页冲突保留原终局存档，重新加载可结算一次。

存档可选字段 exploration，Worker 能力 regionExploration:1。云端拒绝删除或倒退已完成事件、访问地点、营建和累计寻访收益；旧 Worker 在前端上传前被拦截。先更新 Worker，再发布前端；无需 D1 迁移。本轮不包含 APK 重打包或线上发布。

检查：npm run test:shuihu-region、npm run test:shuihu-region-cloud；浏览器运行 scripts/shuihu-region-browser.mjs 与 scripts/shuihu-battle-outcome-browser.mjs。覆盖旧档、固定地图与门槛、实战救人／委托、时长与暂存上限、精确扣料、一次性奖励、Worker 往返、移动端地图、自动结算、重复点击、刷新、保存失败和多标签页冲突。


## 第二片完整区域：芦苇泽

入口：江湖 → 区域探索 → 芦苇泽；特殊副本总览与安道全邀请页也能直接进入。旧矿洞与芦苇泽各自保存当前位置、访问地点与事件，切换地区不重置进度。地图显示六处地点及连接，任务栏可直接查看下一处目标。

- 浅水苇道沿用普通芦苇泽战斗；毒水湾沿用涉毒浅滩路线，多一条毒蛇，全敌气血 +10%，全队开场中毒，每 2 秒受到 3% 最大气血毒伤、共 4 次。胜利必得药草 3，其余装备与药材保持既有概率。两条路都不耗体力、粮草，不派士兵；手动用药照常扣除。
- 草庐结识安道全。走通任一水路后，可用解毒丹 1，或药草 6、粗布 2 救治药农冯伯；两种方式任选其一，只支付一次。
- 冯伯指出泽兰药圃，用行囊木材 3、粗布 1 清沟护苗，不扣山寨营建木材。整修后芦苇泽派遣每批泽兰额外 +1；原暂存不追补，原有三次通关发现加成仍保留。
- 两条水路同难度合计五胜后挑战沉船蛇巢，沿用药船首蛇蓄势毒雾机制。胜利后可取小药箱（浓制药引 2、解毒丹 2，仅一次），并返回草庐邀请安道全；已拥有者只完成委托，不重复发人物或信物，不改变招贤概率与保底。
- 完成邀请且配药间建成后：芦苇泽派遣每批药草额外 +1；地区金疮膏配方泽兰由 4 减为 3。配药间原本的药草减耗仍生效，成品数量、碎银与共享每日加工次数不变。寨中故人页、采集点说明与配方页都显示收益。

存档在 exploration 下增添可选 marsh 与 activeRegion；原旧矿洞记录原样兼容。Worker 增加 marshExploration:1，旧服务会在上传前提示更新；云端阻止旧客户端覆盖掉芦苇泽事件与已访问地点。先部署 Worker，再发布前端，无需 D1 数据库迁移。本轮不发布线上或重新打包 APK。

检查：npm run test:shuihu-marsh、npm run test:shuihu-marsh-cloud、npm run check:shuihu-marsh。覆盖真实胜败与撤退、毒伤与额外药草、两种救治的原子扣料、药圃增产不追补、安道全已拥有分支、一次性药箱、共享制药次数、派遣上限、旧矿洞共存、文件与 Worker 往返、旧服务阻断，以及手机／桌面完整操作。
