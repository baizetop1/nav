# 0.57.0：阵容打法、装备特效与目标追踪

这轮按五项清单完成了一个可试玩版本：三套打法、装备特效与重复件用途、培养目标、六个人物任务、手机操作。接在 0.55、0.56 的本地改动上，未推送或部署。招募概率、特殊副本掉落概率及资源掉落表保持原值。

## 1. 阵容与敌人

铁匠铺 → 养成目标 → 阵容搭配，可选择并追踪三套打法。参考人物可替换，集齐装备不是入场条件。

| 打法 | 参考队伍 | 对应敌情 |
| --- | --- | --- |
| 护阵反击 | 林冲、鲁智深、白胜 | 炉底密窟：头目蓄势三秒后横扫全队，可护阵承受或打断 |
| 打断追击 | 林冲、燕青、白胜 | 地宫内室：头目蓄势三秒后为敌方全队治疗，可打断或先集火头目 |
| 治疗解毒 | 林冲、安道全、白胜 | 芦荡药船：头目蓄势三秒后施加毒伤，可打断或治疗净化 |

打断队进入战斗后，在军令中启用“保留打断招式”。路线会检查是否已有解锁打断招式的好汉。药匣要求穿戴者实际恢复气血，满血溢出不触发。反击要求当时身有护阵且受到了直接伤害，中毒不触发反击。

只有新版开始的战斗接入这些效果；升级前已经进行中的战斗沿用旧行为，避免读档改变敌情。三个密室入口仍要求对应原区域、对应难度通关五次。

## 2. 九种装备特效与精修

| 装备 | 特效 |
| --- | --- |
| 拒马枪 | 有护阵时受直接攻击可反击，每四秒一次 |
| 叠片甲 | 每第三次普攻后为自己护阵 |
| 包铁护心镜 | 有护阵时受击，保护气血比例最低的同伴，每六秒一次 |
| 雁翎短刀 | 本人成功打断后追加伤害，每六秒一次 |
| 窄袖行衣 | 本人成功打断后恢复自身气血，每六秒一次 |
| 行军筹牌 | 本人成功打断后增加全队存活者怒气，每六秒一次 |
| 守炉重锤 | 普攻移除目标护阵，每八秒一次 |
| 芦荡药匣 | 有效治疗后清除受疗者一项毒伤或流血，并护阵，每六秒一次 |
| 地宫残兵书 | 本人成功打断后降低敌方攻击，每六秒一次 |

前三件组成反击路线，中间三件组成打断路线；最后三件仍来自原有密室概率掉落。属性比较、掉落卡、掉落表和装备详情均显示特效。战后复盘记录人物和装备各自实际触发次数；伤害仍受战斗防御、护阵等规则影响。

这九种装备可在铁匠铺 → 装备强化展开“精修特效”。每阶消耗一件同款、碎银 100/200/300、碎铁 5/10/15，必成，最高三阶。每阶使数值效果提高 15%；守炉重锤改为缩短触发间隔。精修不提高掉率、不叠加触发次数。

材料必须未穿戴、未锁定、未强化、未精修；界面列出准确装备编号，点击确认后才消耗。锁定主件可以继续培养，保护限制针对被消耗的材料件。同一种人物任务本领与装备特效同时存在时，只使用装备效果，不触发两遍。

## 3. 下一步目标

沿用一个当前培养目标，可追踪打法、指定装备或人物任务。寨子首页显示目标进度和下一步按钮；完整条件按需展开。

- 打造目标直接打开对应装备，不必翻整份列表；分类按钮可返回完整分类。
- 已有装备可直接打开筛选后的装备列表。
- 密室尚未发现时，跳转原区域并显示入口通关次数。
- 任务目标直接定位对应人物的等级、营建或任务页面。
- 选中目标后立即显示进度；刷新和云端读档保留目标。

进度中的密室胜场使用历史成绩，不要求重复刷一次。概率装备仍可能多次未掉落；界面不会把指定次数写成必得。

| 人物 | 任务 | 达标后新增本领 |

具体通关要求以任务页面为准，沿用原有任务次数、体力和粮草规则。首次达标仍发本人招式书二本、灵蕴二份；未达标不解锁、完成后不能重复领取。个人任务放在人物页前部，成长记录与往事折叠收起。

## 5. 审查顺序

1. 铁匠铺 → 养成目标：追踪“护阵反击”，回寨子检查下一步；点击“准备打造”确认只显示目标装备。
2. 铁匠铺 → 装备强化：用一件未强化、未锁定的同款作材料精修，核对扣费、剩余装备和说明。
3. 历练 → 特殊副本：在三个密室观察蓄势；尝试保留打断招式、调整前排或让治疗携带药匣。战后查看复盘触发次数。
4. 好汉 → 人物任务：选择上述六人之一，检查条件、剧情与达标后的本领。
5. 刷新页面再打开目标和装备，确认进度保留。手机可在 320、390 宽度下检查；长列表仍使用原有分页，未承诺所有内容同时挤进一屏。

## 验证与边界

本轮验收：87 项游戏自检全部通过；生产构建成功（导航站原有主包超过 500 kB 的体积提示仍在）；新功能及原有终局流程均通过 320×568、390×844、1280×900 浏览器检查，未出现页面横向溢出或脚本异常。测试日志与截图在 artifacts/tactics*。

自动化覆盖三套队伍的真实战斗、时间步长一致性、中途存读档、特效触发及冷却、人物本领与装备同类去重、精修材料保护、六个人物任务真实达标、新字段云端往返、旧 Worker 拦截以及精修进度降级保护。手机和桌面验收覆盖目标跳转、指定打造、实际精修、比较、人物目标、密室说明和刷新。

测试使用构造的阶段存档验证玩法可用；尚不能证明普通玩家从新档收集这些装备的耗时合理，也不能证明长期留存改善。后续应根据试玩记录判断材料成本、掉落等待和三套打法的实际收益，不通过增加每日必做来延长时间。

## 存档与发布

版本 0.57.0，云端能力新增 tacticsExpansion: 1。精修、战法快照及复盘、新培养目标写入现有存档 JSON；不新增数据库表，不需要执行迁移 SQL。旧存档可以继续读取。新前端遇到旧 Worker 会提示升级，避免上传后丢失新内容。

发布顺序：先测试、构建，再更新云存档 Worker，最后推送前端。命令在项目根目录执行，每条成功后再运行下一条：

~~~bash
npm run test:game
npm run build
npx wrangler deploy --config cloud/shuihu/wrangler.json
git status --short
git add public/game cloud/shuihu scripts docs package.json
git commit -m "完善阵容打法、装备特效和培养目标"
git pull --rebase origin main
git push origin main
~~~

提交前检查 git status，确认待提交内容；若仍有未暂存改动，应先检查并提交对应文件，或暂存明确与本次无关的工作，再拉取。遇到 rebase 冲突先解决冲突，不要强制推送。已有自动部署以前端托管平台配置为准。

本轮未推送 GitHub、未部署 Worker、未打包 APK。APK 若包含内置页面，需要另行重新构建才能带上新版。
