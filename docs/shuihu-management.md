# 白泽水浒 0.14.0：经营事件、装备对比与服务器演武

本轮完成上一批之后的三项开发：经营事件、穿戴对比与材料入口、服务器计算周本成绩。保留原有云端进度榜，另设服务器演武榜。

## 寨子经营事件

每完成三次寨务，若没有未处理来报或外派任务，会出现商队来访、流民投奔、粮仓告急或匪徒扰寨。来报保留，不会因刷新消失或自动扣除资源。

可以用明确列出的物资换取回报、派一位 10 级好汉外出办理，或暂不受理。外派耗粮 10，十分钟后手动接回并领取酬谢；期间移出编队，不能出战或任职，任职/驻守者须先撤职。领取不自动替换现有阵容，重复领取被拒绝。匪患还可亲征：沿用山林出征消耗和战斗，胜利额外发一次事件酬谢，失败/撤退保留来报。

新增可选 `affairs` 保存来报、外派截止时间与办理次数。存档校验和云端投影均保留这些字段；旧 Worker 会被能力检查阻止接收新寨事进度。

## 装备与材料

在行囊或打造页选择穿戴者，点击“对比后穿戴”，查看人物属性、套装启用/失效情况，再确认方案。转交装备会同时展示原穿戴者和接收者。比较计算包含强化、被动技能、套装、坐骑、品质；不包含临时战场军令和地形。预览不修改存档。

养成目标的材料行新增“查看获取副本”，直接打开对应材料本/当期周本的第一档规则；未开放的日期仍会说明条件。已有筛选、锁定和材料追踪保留。

## 服务器演武榜的范围

入口：存档 → 选择云端编号、输入该编号密钥 → 展开“参加服务器演武” → 选择层数。使用已上传且已收兵的云端阵容，服务器重新构建战斗，按自动技能、寨中军令、当期副本机制计算。第一层通过后才能挑战第二层，每期最多五层；重打只保留最高成绩。服务器日期决定期数，服务器种子决定随机序列，不采信请求中的分数、耗时、气血或存档周本记录。

演武不会扣除本机/云端资源，也不发材料或名次奖励，因此重复提交不会重复领奖。普通游戏周本的首通材料与原有防重机制继续有效。演武成绩存入独立 D1 表，上传/回滚游戏 JSON 不能伪造或覆盖它；接口需要存档密钥和准确云端版本，条件写入阻止读取之后云档已变化的请求。榜单只公开编号、层数、分数和名次。

**边界：验证的是战斗计算，不是所有养成资源的来源。** 好汉、品质、装备仍来自可导入的云端存档，无法将本功能称为完整反作弊系统；未将旧进度榜包装为可信竞赛，也未增加名次奖励。要举办有价值奖励的竞赛，还需把养成交易改成服务器授权记录。

## 现有云端升级（Git Bash，在原项目根目录）

先创建独立排名表，再部署 Worker。迁移只有 `CREATE TABLE IF NOT EXISTS`，可重复执行，不改动已有存档和历史表。

```bash
cd /f/nav-main/nav-main
npx wrangler d1 execute baize-shuihu-saves --remote --file cloud/shuihu/migrations/0002_verified_ranking.sql --config cloud/shuihu/wrangler.json
npx wrangler deploy --config cloud/shuihu/wrangler.json
```

静态文件通过现有 GitHub 流程发布。新站点直接使用更新后的 `schema.sql` 已包含排名表。`/v1/game-version` 增加 `management:1`、`verifiedRanking:1`。新增 `GET /v1/verified-leaderboard` 与需要授权的 `POST /v1/slots/:id/verify`（JSON `{tier:1..5}`、`If-Match`）。现有服务地址和密钥配置保持不变。

本地测试不连接生产云档，也没有执行以上真实迁移或部署。验证包括实际 Worker 与 SQLite 执行四期二十层演武、伪造分数无效、日期/种子替换、越层拒绝、鉴权与并发保护、重复提交不改资源，以及手机端经营、穿戴预览和排名完整操作。
