# 0.56.0：密室、战役回顾与人物本领

承接 0.55.0 的材料加工与新式兵甲，完成该轮清单中第二至六项。旧存档可以继续使用，不重置主线、抽取概率或人物培养。

## 特殊副本

历练 → 特殊副本：每个原区域增加一个密室。对应难度的原区域通关五次即可发现入口；密室的险境、深处还须先通关密室上一难度。解锁次数按存档保存。

| 原区域 | 密室 | 开场机制 | 专属装备 |
| --- | --- | --- | --- |
| 旧矿洞 | 炉底密窟 | 头目 30% 护阵 12 秒，守卫怒气 60 | 守炉重锤：攻击 64、防御 16、速度 -2 |
| 芦苇泽 | 芦荡药船 | 毒蛇怒气 90，狼速度 +30% | 芦荡药匣：气血 180、谋略 32 |
| 荒祠地宫 | 地宫内室 | 头目怒气 80，两翼速度 +35% | 地宫残兵书：攻击 24、谋略 26、速度 3 |

- 各有三档难度，好汉独行；体力、粮草为零，次数不限。手动使用药品仍消耗库存。
- 每个密室五种独立概率掉落，含材料、药品或专属装备，允许空手。
- 专属装备每次胜利的掉率为寻常 2.5%、险境 3.25%、深处 4%，无保底。掉落表展示实际结算概率。原特殊副本的概率不变，总计 49 种不同掉落。
- 密室装备不能购买或打造；新式锻造装备与密室装备均不进入普通战后装备池。装备已满时沿用原有容量保护。
- 深处密室按有装备的队伍验证；等级门槛不是通关保证，可先在寻常档积累材料和装备。

## 战役回顾

历练 → 战役回顾：第三卷起，完成的战役可重打。温习档敌军气血、攻击、防御、谋略按原战役的 65%，实战档按原战役属性。速度沿用战斗引擎原规则。后五卷保留增援、护送与已经取得的准备效果。

不耗体力、粮草，不带士兵，不使用战斗药品，不消耗待携烟幕。不发经验、材料、首通奖励，也不推进日常胜场、组合熟练和正式剧情。独立记录每战每档通关次数及最快时间，保留复盘；战斗中可以保存、退出后接续。

正式完成十二卷后，开放守泊护乡、渡海安家、护民归乡三条终卷路线的回顾。每条路线打完三战后，可展开阅读对应结局。正式结局与已经领取的奖励保持不变。第三至七卷回顾保留该战基础敌阵；后五卷接入完整分波机制。

## 人物任务与本领取向

新增武松、杨志、吴用、公孙胜、关胜、戴宗六个实战任务，当前共有十五个人物专属任务。入口为好汉 → 人物任务；条件、实战进度和失败原因共用同一套检查。沿用每天合计三次、体力 10、粮草 5 加实际兵力一半的消耗。任务达标首次结算发放本人招式书 2、灵蕴 2，并永久解锁任务本领。

已完成专属任务的好汉可以选择：

- 攻势：主动招式伤害 +8%，不增加普攻和药品效果。
- 守势：开战获得 8% 护阵，持续 8 秒；同类护阵沿用原有覆盖规则。

首次选择免费，改选花费 50 银。战斗中不能改选，下场战斗读取所选本领。并非所有人物都已拥有专属任务；本轮扩充六人，没有把未开发人物标成已完成。

## 收支与操作

- 出征准备 → 敌情，山寨出征、基础资源、特殊副本和回顾可展开收支预算。快胜、苦战、败退是固定情景示例，不是胜率预测。银、粮分别列出；计算入场粮耗、伤兵治疗和阵亡补员，募兵折扣也计入。补员按每人成本折算，实际募兵仍按所选批次扣费；随机装备、药品不折算为固定收入。
- 玄铁加工改为 20 银、淬炼钢 1、精铁 1，每日四份；图纸加工费改为 30 银，材料与每日两份上限不变。已有配方无需重新学习。使用副本材料加工能减少碎银支出，不建议为精炼玄铁临时买齐全部原材料。
- 结算 → 掉落明细，新装备可直接锁定，或打开现有属性比较与穿戴界面。锁定后不能分解。
- 特殊副本保留本次区域、难度；装备筛选不再清空打造分类。缺料跳转沿用 0.55.0 的加工和副本掉落表入口。
- 手机密室、回顾主操作置于首屏，规则和结局说明按需展开；其余长内容沿用分页。修复人物选择器多余左边距导致右侧被裁切的问题。

## 存档与发布

新增可选的回顾记录与本领取向；旧存档没有这些字段也可读取。云端能力接口新增 `endgameExpansion: 1`，发布版本为 `0.56.0`。前端阻止向旧 Worker 上传新进度；新 Worker 阻止普通上传抹去已经保存的回顾成绩、人物任务和本领取向。主动历史回滚仍走原有专用操作。

**需要更新云存档 Worker，不需要执行数据库迁移 SQL。** 先更新 Worker，再发布前端。此次没有推送、部署线上或重打 APK；旧 APK 中的内置页面不会自动变成新版。

在 Git Bash 进入项目根目录，每条成功后再执行下一条：

```bash
cd /f/nav-main/nav-main
npm run test:game
npm run build
npx wrangler deploy --config cloud/shuihu/wrangler.json
git status
git add public/game cloud/shuihu scripts package.json docs

git pull --rebase origin main

```

如果 rebase 报冲突，先处理列出的文件并执行 `git add <已解决的文件>`、`git rebase --continue`，成功后再推送。不要强制推送覆盖远端。已绑定 GitHub 自动部署的站点随后会按原有流程发布。
