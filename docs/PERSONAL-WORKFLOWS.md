# 白泽个人工作流

本轮在现有导航、Inbox、阅读与发布功能上增加六组功能。首页以工具按钮打开，管理功能仍放在后台。

## 1. 智能整理

入口：管理导航 → 智能整理，或 Ctrl/Cmd K 搜索“智能整理中心”。

- 查看重复地址、已确认异常、缺少介绍/标签/图标的网站。
- 区分有历史记录且 30 天未访问、保留期内无访问记录。统计只反映本站记录及已同步数据。
- 选择网站，批量修改分类、标签和介绍；先预览，再确认保存到本地草稿。
- 重复地址由用户选择保留对象，确认后移除其他网站及布局。保留对象的内容不变，不合并历史点击数。
- 分类建议来自已有分类关键词及同主机网站，属于本地规则建议。导入 HTML/书签预览也可应用建议。
- URL 去重保留查询参数、锚点和路径末尾斜杠；健康报告必须与当前 URL 匹配才使用。

修改后仍需“提交并部署”才能更新公开导航。

## 2. 网页收集

入口：首页“收集网页”，或已安装 PWA 的系统分享入口。

系统传来的网址、标题和文本先进入可编辑预览；只有点击保存才写入 Inbox。收到分享后立即清理地址中的分享参数。桌面可以将面板中的“收集到白泽”拖到书签栏，在其他网页上收集当前地址、标题及选中文本。无法读取剪贴板时可以手工粘贴。

系统分享目标依赖浏览器与系统支持，并要求先安装 PWA；不支持的设备使用复制粘贴。关闭面板保留本次页面会话中的未提交内容，刷新前请先保存。

## 3. 工作会话

入口：首页“工作会话”。填写任务，可选一组工作网站。番茄钟提供 25/5、50/10 两种专注/短休息预设，也可自定义专注（1–180 分钟）、短休息（1–60 分钟）、长休息（1–120 分钟）。预设长休息分别为 15、20 分钟。

完整完成每 4 轮专注后安排长休息；提前结束只记录实际专注时长，不累计完成轮数。休息不记为工作时长。专注结束后显示提示，由用户点击“开始休息”或“跳过休息”；休息结束同样等待手动开始下一轮，不会自动连续运行。

“沉浸专注”打开独立全屏覆盖画面，可选择纸白、林间、夜色或本站山水静态背景。大时钟、任务和主要计时按钮保持可见，运行中无操作 4 秒后淡出辅助栏，移动鼠标或键盘操作即可恢复；焦点在控件上或网站抽屉打开时不隐藏。Esc 或“退出沉浸”只返回紧凑卡片，不停止计时。背景和声音设置保存在本机，进入沉浸本身不会强制启动计时。

到时提示音默认关闭，仅在用户开启并解锁浏览器音频后播放；同一结束事件跨标签页尽量只提示一次。后台冻结、系统休眠和浏览器策略可能延迟或阻止声音，超过一分钟的旧完成事件不补响。文字提示与完成记录会持久保留，重新打开时补结算当前一段，不追赶之后的多轮计时。

背景声音是独立播放器，提供雨声、溪流与白噪音三种**本地合成环境音**（不是实地录音或歌曲）。无需下载音频，支持离线使用。工作卡片直接显示控件，沉浸画面底部“背景声音”打开同一个播放器；展开面板不会开始播放。可试听 5 秒或持续循环，音量 0–100 独立于到时提示音。

背景音默认不播放，只记住上次选择的声音类型和音量。手动点击播放后，暂停/结束计时或退出沉浸均不会停播；收起工作会话、切到其他页面或刷新会停止。刷新后必须再次点击播放。系统中断音频时显示重试提示，不擅自恢复；支持 BroadcastChannel 的浏览器中，在另一标签页手动开始播放会停止原标签页，避免叠音。

开始后隐藏热榜，已选择组合时首页只显示组合内网站；暂停时间不计入专注。刷新后恢复倒计时，结束时保存最近工作小结。批量打开可能被浏览器拦截，面板始终提供逐个打开的链接。

会话计时依据本机时间，不要求页面持续在前台；不提供关闭浏览器后的系统提醒。运行中的会话保留在当前设备，不通过日常跨设备同步启动另一台设备的计时。完整备份可携带工作会话数据。

已打开的工作会话面板会接收其他标签页的变化。每次保存先比较上次持久化状态，支持的浏览器还会串行写入；旧页面的计时或结束操作遇到新状态时停止覆盖并提示。保存失败保留本页内容，重试也重新检查冲突。

## 4. 全局搜索

### 首页入口整理

首页“整理入口”可调整顺序、显示/隐藏和固定工具。普通模式优先展示固定项，默认最多 6 个入口，其余放在“更多工具”；工作模式只直接展示固定项。隐藏入口不会关闭已打开的面板，全局命令面板仍能访问工具。设置先编辑，再点击保存，纳入完整备份和私人设置同步；另一页面已修改时停止覆盖。

模块加载或渲染出错时提供“返回导航 / 关闭”和“刷新页面重试”，不会自动刷新、删除草稿或清空缓存。已保存内容仍保留，未保存编辑需要用户先保存。

Ctrl/Cmd K 可搜索网站、文章、Topic、Inbox 正文、临时访问、翻译原文/译文、稍后阅读和 Tech OS。私有内容只在本机检索。结果支持全文预览、复制和回到来源；已删除记录不出现。

示例：

- `g React hooks`：使用现有 Google 搜索入口。
- `=2*(3+4)`：安全计算器，无 JavaScript 执行。
- `10 km to mi`、`32 F to C`、`1 GiB to MB`：单位换算。
- `时间戳 1700000000`：时间工具。

面板设置可以添加自定义别名，如 `mdn` 对应 `https://developer.mozilla.org/search?q={query}`。模板使用 HTTPS，查询词会编码，不能覆盖内置前缀。

## 5. RSS 订阅

入口：首页“RSS 订阅”。可添加公开 RSS/Atom 地址，导入或导出 OPML，按来源/关键词/未读/收藏筛选文章，并加入稍后阅读或 Inbox。

订阅配置有两份：本机草稿与仓库中已发布配置。新增订阅先留在本机；在面板中确认公开范围，输入运行时 PAT，才提交 `data/rss-sources.json`。内容权限需允许写入该仓库。其他设备已改变配置时会停止覆盖；先导出本机 OPML，等新版本部署后刷新并核对。

推送部署流程和每小时热榜流程都会运行 `scripts/update-rss.mjs`，生成 `public/rss-feed.json`。每日链接检测部署保留上一份 RSS 报告。定时运行由 GitHub Actions 调度，不能保证严格整点执行。面板“刷新”重新读取已生成的报告，不直接抓取外部网站。

订阅列表与抓取摘要部署后公开；已读、收藏及未发布订阅草稿默认只在本机，也可随私人数据加密同步。不要把含私人订阅令牌的地址提交到公开配置。

抓取按来源设置超时、大小和数量限制，拒绝本地/保留网络地址和重定向到这些地址的请求。单个源失败保留该源上次有效内容及原抓取时间，并显示错误；不会将失败标为更新成功。缓存的是摘要，不是外部文章全文。

首次使用默认没有订阅，需添加或导入来源。首次部署后才具备新的 RSS 抓取工作流。

## 6. 离线与待同步

入口：首页“待同步”；断网后显示“离线草稿”。

- 导航变化逐项列出新增、修改、删除与布局调整，和本站构建版本或最近成功提交比较。
- Inbox、学习打卡、设置与阅读分别显示私人数据同步状态和最后同步时间。
- 导航通过后台读取远端并发布；私人记录通过 Inbox 加密合并。联网不会自动提交，不保存 PAT 或加密密码。
- 远端导航冲突按网站、分类、布局逐项选本机或远端，确认后生成合并草稿。
- 发布成功提交不等于部署完成；部署状态继续在管理后台跟踪。
- “博客与 Tech OS”清单列出已存本机的文章和工作副本，区分待提交、仓库草稿与提交后的部署状态。博客只有在对应提交确实查询到 Pages 成功后才显示已确认上线；刷新后的未核对状态不会当作上线。
- 可批量备份与恢复工作草稿，也可从新版完整备份中单独提取草稿。备份保留博客源文件 SHA、原文和 Tech OS 的 base/files/conflicts，不包含连接表单中的凭据。
- 恢复先预览：相同内容不重复导入，博客同编号的不同内容另存副本；已有不同或损坏的 Tech OS 工作副本保留本机并显示未恢复原因。Tech OS 冲突内容仍在备份文件中，可在没有该工作副本的新浏览器恢复后核对，不自动覆盖。
- 仅收录当前配置仓库中已成功保存的草稿；仍在 AI 向导中的会话内容、保存失败后只在页面内的正文需要先单独导出。未配置仓库的备份不会恢复到其他仓库。

生产构建生成离线资源清单，提前缓存管理、Inbox、工作会话等按需模块。第一次在线打开并完成离线安装后，即使之前没打开过管理页，也可离线编辑并保存草稿。外部网站、翻译和 GitHub API 仍需网络。

每次有效构建产生独立的离线缓存版本。新版本就绪时提示更新，由用户先保存编辑内容再刷新，避免更新过程中打断输入。

## 保存范围与验证

番茄钟额外提供 `npm run check:pomodoro` 浏览器验收，覆盖桌面/手机沉浸画面、预设与自定义、暂停刷新恢复、第四轮长休息、手动切换和声音去重。`npm run test:work-session` 包括 v1 迁移、周期结算与多标签页冲突自检。

背景音使用 `npm run test:pomodoro-ambient` 验证资源清理、切换竞态与音量边界；`npm run check:pomodoro-ambient` 在原生 Web Audio 下验证实际非零音频输出、静音、试听停止、同实例沉浸切换、偏好恢复、多标签页互斥和无音频支持时的错误提示。

完整备份包含搜索别名、RSS 订阅/阅读状态、工作会话，以及已保存的博客副本和 Tech OS 工作副本。原有 GitHub 加密云备份同样收录这些工作草稿；日常 Inbox 加密合并同步仍不收录工作草稿。RSS 阅读状态按条目合并，运行中工作会话留在本机。凭据和 RSS 摘要缓存不进入同步数据。旧版完整备份仍可恢复，不会清空独立工作草稿。

`npm run test:working-drafts` 验证草稿和完整/加密备份往返、远端基线、同编号副本、重复导入、容量失败回滚和已确认部署标记。`npm run check:working-drafts` 在桌面及手机检查清单、下载、恢复预览和存储失败；全部使用隔离的本机数据并阻断远端写入。

## 7. Tech OS 学习反馈与复习

任务的逐步辅导新增“我的回答”“实际观察 / 证据”“卡住的地方”和自评。反馈手动保存，与打卡和正式 Quest 完成状态分开；未保存输入会阻止切换任务、步骤或离开工作台，并可导出独立 JSON。损坏记录、容量不足或其他标签页已修改时，不用旧输入覆盖原记录。

“保存并安排复习”按初次自评安排 1 / 3 / 7 天后的复习。侧栏“复习与反馈”可查看到期和全部记录、回到原步骤；根据新的自评记录本次复习后逐步延长间隔，最多 30 天，不清楚时回到 1 天。日期基于本机时间，仅提供页面内清单，不提供浏览器关闭后的系统通知。

记录位于 `baize_study_feedback_v1`，包含个人笔记和复习日期，纳入完整/加密云备份，也可随 Inbox 的私人工作区加密同步。不同步骤分别合并；同一步骤的并发不同笔记保留为冲突副本，需核对并明确保存后清除，不写入公开教案。学习打卡现也纳入完整备份；旧备份缺少这些新增字段时保留本机记录。

验证：`npm run test:home-tools`、`npm run test:study-feedback`、`npm run check:app-enhancements`。浏览器验证覆盖桌面和手机，并拦截模拟所有外部写入。

运行 `npm run verify:app` 检查类型、生产构建和非游戏自检。浏览器流程使用 `npm run check:personal-workflows`、`npm run check:rss-capture` 和 `npm run check:work-session`；需要本机 Playwright 和 Edge，以及已启动的生产预览服务。默认地址为 `http://127.0.0.1:5189/nav/`，可用 `BAIZE_APP_URL` 调整；Playwright 不在项目依赖时可用 `BAIZE_PLAYWRIGHT_PATH` 指向其安装目录。测试使用独立浏览器环境和模拟响应，不向真实 GitHub 写入数据。
