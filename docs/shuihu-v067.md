# 0.67.0 探索、装备与人物任务

本轮完成六项改进。代码尚未推送或部署，先在本地审查。

## 1. 结算后直接看掉落

快速结算后用小条显示本次物品，优先显示装备和珍稀材料，可查看明细、比较装备、再战或收起。不强制打开整页奖励；刷新和重复点击不重复结算。`新` 表示结算前行囊里没有该物品，并非永久的首次发现记录。

## 2. 掉落装备接上配装

从掉落条打开装备比较，优先选择满足装备本领条件的好汉，也可查看其他合适人选；穿戴后能返回原副本。

新增三件可打造的精品装备，使用已有材料：

- 行医束带：治疗后仍不足半血时，额外恢复最大气血的 5%，冷却 8 秒。
- 追寇短刀：普攻命中破甲或虚弱的敌人时，追加攻击力 30% 的伤害，冷却 5 秒。
- 护身软甲：受直接攻击后不足半血且仍存活时，解除一层中毒或流血，并取得短时护身，冷却 12 秒。

实际效果计入战斗与复盘。原抽取概率及特殊副本掉落表不变。

## 3. 三段探索

入口：副本 → 特殊副本 → 矿洞、芦荡或旧营 → 三段探索。

连续三战，前段气血带入下一段。每次胜利后可绕过守卫歇脚、救下采药人或追查藏货。歇脚只恢复仍存活的好汉；另两条路增加敌军，胜利后额外给药草或碎铁。每战依旧按原表随机掉落，无体力和粮草消耗，战斗中用药实际扣除。

可以在选路时收队，保留已经得到的物品；失败或撤退不追回前段所得。中途刷新、导出和云端保存均保留选路进度。

## 4. 六位好汉的专属任务

新增薛永、项充、李衮、宋清、乐和、樊瑞的任务及完成后的本领。人物任务总数由 27 项增至 33 项。入口仍在好汉的任务页，沿用原有解锁、体力、粮草和每日次数规则。

## 5. 十二卷正常推进检查

修正主线提示把“剧情历练次数”引去不计次数的材料副本，以及未开篇时忽略前置条件的问题。

新检查从新存档开始，通过正常操作招募固定伙伴、练级、购买强化装备、募兵、治疗和用药。除推进恢复与刷新时间外，不注入角色等级、资源或剧情标记。走完十二卷的同一条收尾路线：

| 随机种子 | 模拟经过天数 | 主线战斗次数 | 其他战斗次数 | 战败 | 使用药品 | 累计阵亡 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | 14.50 | 38 | 37 | 2 | 38 | 161 |
| 7 | 14.31 | 37 | 37 | 1 | 41 | 110 |
| 81 | 14.17 | 36 | 36 | 0 | 36 | 110 |

阵容为杜迁、时迁、白胜，中后期准备商店装备、强化及 300 人出征方案。战败后实际医治、补兵并重试。天数来自脚本模拟恢复和每日刷新，不是实际游玩时长，不证明长期留存。其他结局由已有剧情回归覆盖，本次未声称三条结局均经过正常开荒审计。

## 6. 战绩与称号

入口：副本 → 战役回顾 → 荣誉与称号。

新增七项目标，包括十二卷通关、三段探索、人物任务、不同回顾规则，以及反击、打断、救护搭配战绩。后三项需在规定难度的密室或原战回顾中，全员存活并实际触发对应本领；记录完成次数、最快用时和当时阵容。

选择一个目标查看，避免手机堆成长页。取得的称号可展示或取消，仅改变展示，不增加属性。

## 验证与发布

已通过 100 项游戏自检、构建，以及 320 / 390 / 1280 像素宽度的新流程浏览器检查。战斗结束、其他结束提示也通过手机和桌面回归。云端检查使用本机打包的真实 Worker 与 SQLite，覆盖中途战斗、选路、结束、称号的读写和旧进度覆盖拒绝；未操作线上存档。

```sh
npm run test:game
npm run audit:shuihu-twelve
npm run check:shuihu-adventure
npm run check:shuihu-battle-outcome
npm run check:shuihu-completion
npm run build
```

浏览器检查需要 Playwright，可用 `SHUIHU_PLAYWRIGHT_PATH` 指向已有安装。

**此版需要同步更新 Worker，无需新增数据库迁移。** 新状态保存在现有存档 JSON 内。旧 Worker 缺少 `adventureLoop` 能力时，客户端会阻止上传这些新内容并保留本地存档；升级后再上传。

发布顺序：先验证 → 更新 Worker → 推送前端到 GitHub。Worker 命令：

```sh
npx wrangler deploy --config cloud/shuihu/wrangler.json
```

GitHub 推送沿用现有仓库流程，先检查变更、提交，再拉取并变基、推送。本轮未替用户执行发布。
