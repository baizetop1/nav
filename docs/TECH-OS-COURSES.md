# Tech OS 新方向 / AI 课程使用说明

这个向导把一个想学的方向整理成可编辑的课程草稿。基本流程是：填写学习条件 → 建立大纲 → 逐课补齐 Markdown 教案 → 人工核验 → 加入 Repository 草稿 → 再确认提交 GitHub。

AI 是可选项。不配置接口，也可以建立本地大纲、手写教案、导入课程 JSON。当前实现不内置免费额度，不代选模型；开发验证使用模拟请求，尚未验证任何真实服务商的连通性、模型权限或 CORS 配置，不能把“功能已实现”理解为“你的接口已接通”。

## 1. 从五项学习条件开始

打开网站的 `#/tech-os`，在侧栏选择“新方向 / AI 课程”，填写：

1. 学习主题：例如“Linux 服务部署”，不超过 160 字符。
2. 已有基础：已经会什么、哪里不熟悉。
3. 希望做到什么：尽量写成可观察的结果，如“能启动一个本机服务，并解释日志中的错误”。
4. 可用时间：每次时长、学习频率与整体期限。
5. 设备与工具条件：操作系统、可用设备、已有工具及安装权限，不要填密钥、私人配置或内部项目内容。

后四项各不超过 2000 字符。AI 生成要求五项全部填写；不要只写“随便教我”，否则很难得到适合自己的操作步骤。

点击“先建立本地大纲（不调用 AI）”可以先得到空正文的课程列表。本地大纲主要根据主题匹配预设模板，并将学习目标放入简介；它不是 AI 个性化推理，不会替你查资料或生成完整教案。目前这个入口至少需要主题和目标。已有向导草稿时，替换前会要求确认。

## 2. 可选：配置自己的兼容接口

### 地址和模型

本功能使用 OpenAI 兼容的 Chat Completions 文本接口，以一次非流式 POST 请求发送 `model`、`messages` 和输出上限。它不是 Responses API 客户端，也不会自动切换协议或模型。接口形状可对照 [OpenAI 官方 Chat Completions 文档](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。

填写服务商或自有网关提供的 Base URL，或者完整的 `chat/completions` 地址。系统只在给定路径后补上 `/chat/completions`，不会猜测缺少的 `/v1`：

| 输入示例 | 最终请求地址 |
| --- | --- |
| `https://gateway.example/v1/` | `https://gateway.example/v1/chat/completions` |
| `https://gateway.example/custom/chat/completions` | 保持该完整路径 |
| `https://gateway.example` | `https://gateway.example/chat/completions`，不会补 `/v1` |

这些是地址格式示例，不是已提供的服务。发送前检查页面显示的“发送目标”。地址不能包含用户名、密码、查询参数或片段；不要把 Key 拼在 URL 里。远程接口必须是 HTTPS，HTTP 仅允许 `localhost`、`127.0.0.1`、`[::1]`；浏览器仍可能限制网页访问本机接口。

“模型 ID”必须自己填写服务商实际开放的完整名称，不超过 200 字符。向导不会自动选择、替换模型，也不会先调用模型列表接口。

### Key 和输出参数

- “API Key / 网关令牌”可留空，适用于不需要这个请求头的本机服务或其他已妥善鉴权的环境；留空不代表公共接口无需鉴权。填写时仅放入目标请求的 `Authorization: Bearer …` 头。
- 请求不携带浏览器 Cookie，不支持自定义鉴权头或查询参数鉴权。若网关只接受 Cookie，需要先调整网关方案，不能靠前端绕过。
- 单次输出上限默认为 6000，允许 256–16000 的整数；这是应用的输入限制，不代表你的模型支持全部范围，也不是总费用封顶。
- 上限参数可选 `max_tokens` 或 `max_completion_tokens`，按服务商文档选。为了兼容部分网关，界面默认前者；OpenAI 官方已将 `max_tokens` 标为弃用并推荐后者，后者还可能包含不可见的推理 Token，不能直接换算成正文字符数。[官方参数说明](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)

### 发送前确认

展开“查看实际发送内容（不含密钥）”，检查目标、模型和正文，然后勾选同意发送。

- 大纲生成只发送五项学习需求和固定教学要求。
- 单课生成另外发送当前课程标题、摘要、课题列表与所选课名；不发送其他课的 Markdown 正文，也不会读取仓库、Inbox、临时文本、浏览记录或 GitHub Token。
- 自己填入需求和课程标题/摘要的内容仍会发送给接口服务商，因此不要把私密材料写入这些字段。
- 修改配置、需求、课程内容或所选课程后，需要重新确认发送。

推荐使用自己控制、有鉴权和用量限制的网关，把上游服务商密钥留在服务端。浏览器 BYOK（自行填写密钥）不等于安全密钥保管：页面脚本、浏览器扩展和接口服务商仍可能接触密钥或内容。不要使用不可信中转站、公开无鉴权代理，也不要把密钥写入仓库、前端 `VITE_*` 环境变量或截图。[OpenAI 官方密钥安全说明](https://developers.openai.com/api/reference/overview#authentication)

跨域访问必须由目标服务正确配置 CORS；本功能不会关闭浏览器安全机制或自动绕过跨域限制。请求禁止跟随重定向，避免把鉴权请求转到另一个目标；需要重定向的网关请直接填写最终兼容地址。

## 3. 先生成大纲，再完善一课

选择“先生成路线大纲”，AI 被要求只返回 2–12 个不重复的问题型课题，每课 `body` 为空。大纲只说明准备学什么，不等于已有可跟做的课程。

有大纲后，在“选择要完善的一课”中选课，把生成范围改为“只生成下方选中的一课教案”。这次生成只替换所选课的正文；若已有正文，会先要求确认。生成失败、取消或返回内容未通过校验时，原稿保留，不会用错误或半截响应覆盖它。重新生成整份大纲成功后则会替换向导中的整个课程包，先下载需要保留的内容。

也可以直接修改“本课问题”和“本课 Markdown 教案”，或在“课程 JSON 原文”中粘贴课程包。建议一课做小，正文应包含：

- `## 开始前`、`## 学习思路`、`## 工具准备`。
- `## 下一步` 下的一个明确小动作，再用 `## 学习步骤` 承载 2–4 个 `### S1 · …`、`### S2 · …` 步骤。
- 每步八个四级标题：为什么这样做、工具与操作、观察与预期、常见误区、卡住时怎么办、检查理解、参考答案、完成标志。
- 待你亲自完成的证据标准和后续深入边界，不写虚构的“我已经完成了实验”。

预览里会显示参考答案，适合审稿，不是隐藏答案的考试模式。逐项检查命令使用的是 PowerShell、Bash 还是浏览器 Console，安装前提是否满足，失败路径是否清楚；打开官方参考链接核验其内容。AI 可能编造链接或给出过时命令，不能直接把建议当作可安全执行的指令。

界面区分“只有大纲”“教案待完善”“结构齐全 · 待人工核验”。结构检查检查标题、步骤、必需栏目和占位内容等，不能证明事实正确、命令安全、链接有效，尤其不能证明你已经完成学习。

## 4. 课程 JSON 导入与下载

下面是可导入的两课大纲示例。两个空 `body` 是刻意保留的待写正文，不会被当成完整教案：

```json
{
  "version": 1,
  "title": "本机 HTTP 服务入门",
  "summary": "在自己的电脑上运行小服务，区分请求、响应和连接失败。",
  "lessons": [
    {
      "title": "浏览器怎样发出一次 HTTP 请求？",
      "body": ""
    },
    {
      "title": "服务器怎样返回状态码与正文？",
      "body": ""
    }
  ]
}
```

包顶层仅允许 `version`、`title`、`summary`、`lessons`；每课仅允许 `title`、`body`。不要增加 `id`、`path`、`status`、Token 或密钥字段；正文也不要附加篇首 Front Matter，仓库 ID、路径与状态由系统分配。

格式限制：

- `version` 必须是数字 `1`，2–12 课，课名不重复。
- 课程标题和课名各最多 160 字符，摘要最多 4000 字符，单课正文最多 60000 字符。
- UTF-8 总大小不超过 512 KiB；中文字数不等于字节数，可能先碰到总大小限制。
- 接受纯 JSON，或一个完整的小写 `json` 代码围栏；围栏外不能混入解释。拒绝重复字段、未知字段和检测到的明显凭据。凭据检测不是完整的数据防泄漏保障，发布前仍须人工检查。

“导入课程 JSON”成功后替换当前向导课程，已有内容时会确认；不直接改仓库。“下载课程包”仅下载课程内容，不包含 API 配置、Key，也不另外保存五项需求表单。暂时无效的 JSON 可以继续修正，但不能作为有效课程下载、用来生成单课或加入 Repository，直到通过校验；仍可根据五项需求重新生成一份大纲。

## 5. 人工确认，再加入 Repository

检查文件预览、课程完整性标记和公开范围，勾选人工核验确认，然后输入界面显示的 `STAGE ROUTE-…` 短语，点击“加入 Repository 草稿”。不要自行套用示例编号，以当前预览为准。

此操作只生成新的路线和任务文件：

- 新路线与新任务均为 `backlog`，路线 `main: false`。
- ID 根据现有内容与待提交草稿分配，遇到路径冲突停止，不覆盖旧文件。
- 不修改当前 Main Route、Active Quest、`state.yml` 或个人学习打卡，也不自动宣布任务开始或完成。
- 只有大纲或不完整教案也可明确作为待完善草稿保存；它们不会因此变成完整课程。

只有本机持久化成功后才会清空向导会话草稿并进入 Repository；空间不足或存储受限时停留在向导，保留原文供下载备份。原有 Repository 编辑、远端基线及未解决的冲突都会保留。进入 Repository 后再执行远端读取与比较、完整校验及明确提交确认。加入草稿不是 GitHub 提交，更不是部署成功；后续启用哪条主路线仍由独立的路线生命周期操作决定。

提交后的 Markdown 可能进入公开 GitHub 仓库和 Pages 页面。这里的课程不是 Inbox 私有密文，请在确认前移除敏感内容。

## 6. 哪些内容会保留

| 内容 | 保留范围 |
| --- | --- |
| 五项需求与向导课程 JSON | 当前 Tech OS 工作台会话；内部切换页面后可继续。刷新、关闭或离开整个工作台前下载课程包；需要保留的需求表单请自行另存 |
| API 地址、模型、输出参数与 Key | 仅“新方向 / AI 课程”页面的内存状态；离开该页后不保留，返回需重新填写，不进入下载包或仓库 |
| 已加入 Repository 的 Markdown 草稿 | 由 Repository 保存本机工作副本；以页面显示“本机保存成功”为准，发布到 GitHub 还需单独确认 |

“清除 API Key”只清除当前表单持有的 Key。页面内存清理不等于可验证的安全擦除，也不能撤回服务商已经收到的请求。刷新前的离开提示只是辅助，不能代替下载备份；浏览器限制或异常关闭时提示可能不出现。

## 7. 超时、取消和常见错误

每次点击生成只发一次请求，不自动重试。最长等待约 180 秒，非流式响应需要完整返回后才预览；响应读取上限为 1 MiB，请求内容也有大小限制。检测到截断、空结果、拒绝响应、工具调用、异常格式或回显本次 Key 时，会拒绝将其作为课程正文接收。

取消或离开“新方向”页面会中止本机等待；服务商可能已经开始生成或统计用量，不能保证取消不收费。手动再次点击会产生新请求，具体费用、额度和退款规则以你选择的服务商为准。

- 400 / 参数不接受：核对最终路径、模型 ID、`max_tokens` / `max_completion_tokens` 和供应商支持的范围。
- 401 / 鉴权失败：检查令牌是否完整、过期或已撤销；不要把真实 Key 发到截图或问题反馈中。
- 403 / 拒绝访问：检查模型权限、网关策略或地区限制。
- 429 / 限流或额度不足：先检查配额和服务状态，再决定是否手动重试。
- 网络 / CORS / TLS / 重定向错误：先确认最终端点和网关配置；前端不能修复服务端跨域授权，也不应关闭证书验证。
- 截断或响应过大：缩小单课范围或按服务商能力调整输出上限，勿把半篇内容当作完整教案。

本功能不会展示服务端原始错误正文，以降低错误响应回显密钥等敏感数据的风险。页面 Token 统计仅采用接口返回的有效数值，不是账单或精确费用估算；未返回统计时不会编造用量。
