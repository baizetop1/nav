108 正册人物全部保持五星招募档，另有固定资质：甲 24、乙 48、丙 36。名单按当前本领与用途确定；甲中有六名地煞，五职业都有甲等，不按梁山座次直接分档。同一个人物每次抽取都使用同一资质，不生成强弱不同的版本。

## 带兵伤亡

旧实现已有伤亡，但快胜基损过低，小额阵亡需要累计多场，简短结算又不显示损失，容易误认为没有消耗。新版把带兵接敌、累计承伤、敌方出手、时长和军令纳入兵损。治疗好汉不会抹去已经受到的部队损耗。

伤兵和阵亡均从可出征兵力扣除。伤兵可用医馆治疗归队，阵亡留下空缺，只能付费重新募兵；固定 10000 精度累计小额阵亡，避免整数舍去后一直不死人。固守降低损耗，强攻提高损耗，随军救护减少阵亡并将这部分转为伤兵。

以下是特定队伍的真实战斗检查，数值不是所有战斗的固定扣除：

| 百兵出征的战况 | 归营 | 伤兵 | 阵亡 |
| --- | --- | --- | --- |
| 30 级队伍快胜，固守 | 97 | 3 | 0 |
| 同队快胜，均衡 | 94 | 5 | 1 |
| 同队快胜，强攻 | 89 | 9 | 2 |
| 1 级白胜攻寨苦胜，37 秒 | 64 | 28 | 8 |

战前立即撤退无接敌兵损；战中撤退按点击时的战况结算。独行、零兵和安全采集派遣不凭空产生士兵阵亡；带兵分队有出发前明确的伤亡风险，人数与小数累计按固定快照各结算一次。没有英雄永久死亡，医治不会复活阵亡士兵。

胜负小弹窗直接显示归营／伤兵／阵亡；营兵页面显示可出征、待治伤兵和累计阵亡，不必翻战报才能知道损失。

## 存档与发布

资质属于固定人物定义，不写进可随机的人物存档。新培养、正式战斗和使用正册人物的分队派遣设置进度标记 hero_aptitude_v1；新带兵战局使用 casualtyRules = 2，收兵后保留营中规则标记。旧正在进行的规则 1 战局继续原结算，读档不重算人物属性、不追扣兵损。

Worker 增加 heroAptitudes:1、combatCasualties:2，并保留 casualtyRules:1 的旧客户端能力字段。新客户端上传前检查能力；服务器拒绝普通上传抹掉新标记、将当前兵损规则降级或减少累计阵亡。显式历史回滚入口仍可使用。本轮使用现有 D1 表，无新增 SQL 迁移。

发布顺序为 Worker → GitHub 网页 → 同包名、同签名 0.84.0 APK（versionCode 58）。真机、后五地新档流程、更多人物事件与长期供需仍在待办内；脚本检查和浏览器操作不等同于真人长期游玩。
