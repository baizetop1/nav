# 白泽水浒 0.50.0：免费寻宝副本

入口：更多 → 特殊副本，也可在历练页的功能切换中选择“特殊副本”。原来的排名仍在历练功能切换中。

## 副本与难度

| 副本 | 主要产出 | 特点 |
| --- | --- | --- |
| 旧矿洞 | 矿料、淬炼钢、驯骑凭记、兵器、盔甲 | 守洞军士开战有护阵 |
| 芦苇泽 | 药草、皮革、药引、药品、行装 | 毒蛇能较早施毒 |
| 荒祠地宫 | 招式材料、灵蕴、经验丹、坐骑饲料、杂装 | 头目提前积怒，伏兵速度较快 |

每处有寻常、险境、深处三档。队中至少一位好汉达到 5 / 15 / 25 级，聚义厅达到 1 / 2 / 3 级；高难度还需要先通关本副本的上一档。

不消耗体力、粮草，不带乡勇，没有每日次数。只有手动使用的战斗药品会实际扣除。已预备烟幕不在此处消耗，留给普通出征。队伍和军令仍可在出征准备中调整，原带兵人数与方式保留。

## 随机掉落

三处各有 16 / 17 / 18 条掉落，共 43 种不同物品或装备。每次胜利按本档掉落表逐条独立判定；可能同时掉多件，也可能一件没有。没有固定经验、银两、必掉物或首通奖。失败、撤退不判定掉落，可再次进入。

“掉落表”按材料、药品、装备筛选，每页显示三件，公开名称、用途、数量范围及本档概率。高档概率按基础值的 1.3 / 1.6 倍计算，部分材料数量范围也增加；界面与结算使用同一份表。招贤令、登仙印和游历兑换装备不在免费掉落表中，原招贤概率保持不变。基础档驯骑凭记概率 1.2%、灵蕴 1.5%；玄铁、兵器图纸、基础技能残页暂未有消耗入口，不加入此次掉落。

战利品在结算时收入行囊，仅结算一次。“战绩”保存最近一趟掉落及每本每档的通关次数。战斗结算提供“再次挑战”，会重新打开出征准备，不会自动扣药或自动开始。

入场前需要留出本趟可能掉落的装备空位（矿洞 5、芦苇泽 5、地宫 6）。材料到存储上限时先使用或加工。即使战斗中发生异常容量变化，结算也不会覆盖已有库存；未能收入的数量会单独列明。

## 存档与发布

新增可选 specialDungeons 记录；旧存档直接兼容。在战、结算、文件导出、云端上传下载均保留副本记录。旧 Worker 会在上传前被拦截并提示更新，本机进度保留。

需要更新云存档 Worker，无须数据库迁移，不用重复执行 SQL。按以下顺序发布：

1. 在项目根目录运行 npm run test:game 和 npm run build。
2. 运行 npx wrangler deploy --config cloud/shuihu/wrangler.json 更新 Worker。
3. 按现有 GitHub / Pages 流程提交并发布前端。

本轮开发不提交、不推送、不部署线上；验证使用本地与内存 SQLite。

## 验证入口

- npm run test:shuihu-special：9 种真实战斗、无资源扣除、失败撤退、用药、容量、读档与重复结算；90,000 次实际掉落抽样检查各条概率、独立性和空掉落。
- npm run test:shuihu-special-cloud：9 种在战档文件 / SQLite 往返，真实结算、异常上传拒绝、通关计数防回退、旧服务上传前拦截。
- npm run check:shuihu-special：360×640、390×844、1280×900 的副本入口、筛选分页、真实出征、结算再次挑战及恢复操作；320×568 的首屏挑战按钮。
- npm run test:game：全游戏回归。
