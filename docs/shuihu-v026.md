# 0.26.0 行军取舍与培养预览

本轮完成上一轮建议的前三项：兵种与战损平衡、首批人物差异化、成长收益预览。没有新增章节、人物或数据库表。第六卷与既有内容保留；第七卷尚未开放，更多人物的专属机制及经营、扫荡和存档界面改进留待后续版本。

## 兵种与兵损

新出征的实际随军部队增加地形伤害修正，英雄独行不受这项部队修正；原有英雄地形专长、兵种克制仍分别计算。

| 地形 | 步军 | 弓军 | 骑军 | 水战部队 |
| --- | --- | --- | --- | --- |
| 平原 | 0% | 0% | +8% | 按所属兵种 |
| 林地 | +8% | +5% | -10% | 按所属兵种 |
| 山地 | +8% | +8% | -12% | 按所属兵种 |
| 水域 | -6% | -6% | -15% | +12% |

带更多兵的收益仍递减，出发粮草按实际人数计算。没有新增自动补员，也没有返还入场费用。

胜利的固定损耗降低，并随战斗时长增长：原军令基础损耗 × 35% × min(1, 0.25 + 战斗秒数 / 60)，再加平均失血比例 × 20%。失败、撤退仍保留原军令损耗、平均失血损耗和额外 20%；寨务敌情的兵损修正继续生效。人数向上取整，阵亡向下取整，因此快速小规模胜利可能没有阵亡。

默认阵亡占损失人数的比例：胜利 20%，撤退 35%，失败 45%。随行救护部队将此比例乘以 90%；安道全乘以 75%；皇甫端按骑军比例减免，最低 85%。救护效果取最强一项，减少的阵亡转为伤兵，避免叠成无损出兵。白胜实际带兵时，非胜利的总损失另减少 10%。收兵后无力再战的英雄仍计入本次随军救护配置。

战前页面增加快速胜利、苦战胜利、败退三个固定场景及恢复兵额所需的粮银预算。这是场景比较，不是胜率预测。战中显示当前撤退预算，以点击时实际战况结算；治疗伤兵需要医馆，可能分多批执行，阵亡只能付费补员。

回归测试发现，战斗节奏变化会让旧章节的个别组合被反复自疗拖至超时。因此新战局的敌军主动治疗在 60 秒后减至 50%、120 秒后减至 25%。我方治疗、药品、副本固定补给不受影响，规则在战前可见，治疗日志会标明衰减。

## 成长预览

- 经验丹确认页增加个人统兵上限、寨主体力上限及本次解锁招式。继续显示等级、剩余经验、五项属性、满级溢出及实际使用数量，取消不消耗。
- 升品页面显示当前配置下五项属性和统兵上限的前后变化；满足原有条件后点击升品才扣费。
- 专属练兵显示本阶到下一阶的实际加成，明确练兵不送士兵、不增加统兵额度。
- 招式显示下一等级的主效果数值；人物成长区列出尚未解锁招式及当前缺少的条件。
- 保留现有逐级递增经验曲线，每颗经验丹仍为 300 经验；等级、品质、装备、经验均不重置。低等级接近升级时，一颗丹可能跨两级，预览会如实显示。

## 存档与发布

存档外层仍为 version 2，名册仍为 5，仍有 112 位人物。新出征在 battle.expedition 中记录 fieldRules: 2；旧的进行中战局没有该标记，继续按旧伤害、旧兵损和旧治疗规则结算。加载不重新应用开战加成。

需要更新云存档 Worker，尤其是上传进行中的新战局及使用服务器演武。前端上传新战局前检查服务的 fieldRules 能力，旧服务会收到明确的升级提示。本轮无需新表，无需执行迁移 SQL。

发布顺序：先 Worker，后 GitHub 前端。开发期间未提交、推送、部署，也未修改生产云存档。

```bash
npx wrangler deploy --config cloud/shuihu/wrangler.json
```
