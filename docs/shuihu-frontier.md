# 白泽水浒 0.11.0 · 经营拓土

本轮将据点占领、定时生产与专属兵种差异串成可玩的流程，保留 0.10.0 的 108 将、立绘、三阶练兵、套装、阵容、材料目标和轮换副本。

## 开始方式

已有寨子的玩家在「寨子」点击「开办经营拓土」。不收取开办费用，不回补更新前的离线收益。随后寨子页显示生产队列，江湖页显示五处领地、路线和敌情。江湖页顶部可以直接切到原有地点全图；各据点按钮可以定位到详情。

招贤、打造、采买仍可直接访问，不要求先占领据点。新开游戏先建立寨子，再开办本功能。

## 据点与路线

```text
寨子 → 青松林场 → 伏牛矿山 → 盘龙敌寨
寨子 → 东溪粮庄 → 石碣渡口 ↗ 伏牛矿山
```

| 据点 | 地形 | 前置 | 聚义厅 / 英雄等级 | 每半小时产出 |
| --- | --- | --- | --- | --- |
| 青松林场 | 林地 | 无 | 1 / 1 | 木材 3 |
| 东溪粮庄 | 陆地 | 无 | 1 / 1 | 粮草 4 |
| 石碣渡口 | 水域 | 东溪粮庄 | 2 / 10 | 粮草 3 |
| 伏牛矿山 | 山地 | 林场或渡口任选一条安全路线 | 2 / 8 | 碎铁 2 |
| 盘龙敌寨 | 陆地 | 伏牛矿山 | 3 / 18 | 碎银 20 |

出征扣体力 10、粮草 6 + 随行乡勇人数的一半向上取整；沿用已保存的英雄、军令与带兵配置。胜利实际改变据点归属，并且仅首占发放首占物资。失败与撤退不占领、不发物资。敌寨中的首领保留蓄力与打断机制。

据点初占或解围后有六小时补给安全期。安排达到表中等级的好汉留守，可持续维持运输；一名好汉只可驻守一个据点或任职一个生产岗位。驻守英雄仍可编入出征队，但实际出征期间暂离驻地，六小时无有效守备后会触发补给敌袭。

敌袭不会删除已积累物资，不会永久夺走人物。它会暂停本据点生产、收取和作为后续进军前置的作用；再次出征解围后恢复，不重复发首占奖励。已经占领的后续据点不会连锁丢失，解围也不要求重打前置。派守将不能直接消除已发生的敌袭。

当前势力是这五处固定的敌方驻军，敌袭按明确计时与守备条件发生；本轮没有实现全地图敌方 AI 扩张。

## 山寨生产

每 30 分钟一批，每个队列最多储存八小时相应产能。上线时间、收取、任职调整与建造前会结算已有时段，不能通过反复换人重算过去产出。材料需要手动收取，已满的队列不会无限增长。

- 农田和伐木场：每批基础产出为 1 + 设施等级。任职辅佐型好汉额外 +3，其余好汉 +2；擅长该资源的乡里帮手 +3，其余帮手 +1。
- 冶铁工坊：建成集市即可使用。每批积累 1 份加工额度，有任职人手时为 2 份。实际收取时每份消耗碎铁 2、木材 2，产精铁 1。原料不足的额度保留，满八小时额度后暂停累积。
- 收取顺序：农田 / 伐木场 → 安全据点 → 工坊加工，因此本次收到的矿山碎铁与林场木材可以马上用于加工。
- 任职英雄只在实际战斗出征时停掉岗位加成，乡人基础生产继续；仅放在待出阵阵容中不会停工。出征与离线暂停的战局都视为尚未返寨，结算收兵后恢复。
- 乡里帮手不计入 108 将，不会进入英雄招募池，可以在生产岗位任职；已有寨务收益设定继续保留。

当前生产使用存档时钟实现离线积累，和已有体力恢复一样，不宣称具备服务端时间防作弊。收获与消耗纳入现有弹窗及每日收支小结。

## 新部队战法

须实际分到至少一名乡勇，仅作用于本次更新后开启的战斗：

| 好汉 | 本部战法 |
| --- | --- |
| 徐宁 | 每第三次普攻命中骑军后追加破甲 4 秒、眩晕 1 秒 |
| 凌振 | 每完成三次普攻，对敌军全体追加 55% 攻击倍率炮击 |
| 时迁 | 开战时全队第一次行动提前 400 毫秒（最早 300 毫秒），怒气 +8 |
| 呼延灼 | 随军时承受普攻伤害减少 10%，不减技能伤害 |
| 李俊、阮小二、阮小五、阮小七、张横、张顺、童威、童猛 | 水域每第三次普攻后回复自身最大气血 3% |

原有水战部队的分阶伤害加成扩展到石碣渡口等水域据点，与水泊周本一起适用。其他部队继续使用原有六类基础战法；本轮没有声称为每一将新增完全独立的战斗引擎。

## 存档与发布

新增可选 frontier（版本 1），保存各生产队列、人员岗位、据点守将、补给状态与生产时钟。新战斗另存 frontierRules=1，旧的进行中战斗不补写此标记，继续原有战法。导入导出与 Worker 均校验、保留这些字段；重复岗位、未知据点、负产出与错误战场会被拒绝。

**先部署 Worker，再发布前端。** 新前端上传前检查 `/v1/game-version` 的 `frontier: 1`；旧服务会被提前阻止。新服务拒绝缺少 frontier 的旧页面覆盖已有领地存档。此次不需要修改 DNS、域名或 D1 表结构。

在原项目根目录运行：

```bash
npx wrangler deploy --config cloud/shuihu/wrangler.json
```

之后按原有 GitHub 发布流程提交代码。开发过程只同步本机文件，不自动推送或部署。
