# 白泽水浒 0.12.0：阵前指挥与整理

## 玩家入口

- 交战页「阵前指挥」可集火指定敌人、切换正常攻守/收势固守、保留打断招式。暂停时可以安排军令，战斗时间和军令间隔一起暂停。
- 招贤馆可消耗 10 张普通招贤令十连，弹窗按顺序展示十次入寨、重复或传闻结果。不会因十连额外保证入寨，不改变概率与保底。专属招贤仍为单次邀请。
- 行囊的随身装备、铁匠铺均可按名称、部位、品质及状态筛选，并锁定/解锁单件装备。锁定允许穿戴和强化，拒绝分解；筛选不改变存档。

## 规则与存档

集火影响普攻和默认单体技能目标。嘲讽优先；追击后排、最低气血、群攻等招式保持各自目标规则。目标退阵后自动自由迎敌。

固守使双方直接伤害都乘以 0.8，降低承伤的同时降低己方输出。治疗、流血和中毒不变。攻守切换间隔为 3 秒战斗时间。留招开启时，已解锁主动打断招式的好汉不自动消耗怒气，直到首领蓄势才尝试打断；仍受怒气、眩晕、冷却限制。其他好汉自动技能照常，手动施招不受留招限制。

旧存档、旧战局没有军令时保持原行为。使用新功能后增加可选 `commandVersion: 1`；战斗增加可选 `orders: {version,focus,stance,reserve,readyAt}`；装备增加可选布尔 `locked`；十连增加最近一组 `recruit.lastBatch`，后续单抽清除此组。只保留最近一组十连，避免存档无限膨胀。

十连在一个事务中预先检查 10 张令，逐次复用单抽结算、保底、相识与章节完成逻辑。全部完成才写入本机；失败不部分扣令。结果汇总弹窗会明确区分传闻和正式入寨。

## 发布

部署静态游戏和 `cloud/shuihu/worker.js`，无需迁移 D1 数据表。Worker `/v1/game-version` 增加 `commands: 1`。新版进度上传前检查能力；旧 Worker 不接收新版上传，旧客户端无法覆盖已有 `commandVersion` 的云档。更新期间本机存档、导出和导入均可正常使用。

使用 `npm run test:shuihu-commands` 验证十连与单抽随机结果/保底一致、锁定、集火/嘲讽、固守双向减伤、留招实际打断、战斗时钟切片一致及存档兼容。`test:shuihu-cloud` 使用实际 Worker 和 SQLite 验证上传、下载、回滚和旧版覆盖保护；`npm run test:all` 与 `npm run build` 为发布检查。

周本仍使用云端存档成绩，未增加服务器重演与反作弊验证；本轮没有改动排名奖励。
