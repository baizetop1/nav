# 白泽水浒 0.44.0：人物搭配、出行计划与江湖留名

本次合并完成 0.40 之后规划的四个开发阶段：人物差异（0.41 范围）、路线变化（0.42）、经营联动（0.43）、长期挑战（0.44）。交付版本统一为 0.44.0。没有发布中间版本，也没有推送 GitHub 或部署云端。

## 人物差异

六位已有角色新增正式出阵本领，不改变招贤概率，不借用到剧情助阵或教学演武：

| 人物 | 实际效果 |
| --- | --- |
| 林冲 | 排首位时开场提供自身 12% 护阵，持续 6 秒。 |
| 汤隆 | 固守或护阵下受到实际伤害且仍在阵中，增加最多 4 怒气；间隔 3 秒。 |
| 白胜 | 招式有效治疗后，为受疗者提供 8% 护阵，持续 4 秒；间隔 6 秒。 |
| 安道全 | 招式有效治疗后，清除受疗者一项流血、中毒、眩晕、破甲或削弱；间隔 6 秒。 |
| 时迁 | 对气血低于一半的目标普攻伤害增加 15%，可配合集火军令。 |
| 王进 | 主动招式实际截断首领蓄势后，使该敌人攻击降低 15%，持续 6 秒。 |

同类护阵、削弱不相加，沿用较高数值和较晚到期时间。已退阵者不获得新的开场保护。既有培养、品阶、兵种、组合与专属任务继续生效。

「好汉 → 等级经验」显示本人本领；「山河 → 出行筹备」可查看搭配参考。结算复盘及最近一战记录本领触发次数。冷却与已触发的效果随战局保存，刷新不会重新触发开场本领。

## 路线与备战

从「寨子 → 出行备战」或「山河 → 出行筹备」保存计划，再到江湖游历选择地区和难度。

三种五段行程：

- 稳行旧道：保留原来的护送、休整与交锋路线，第四段启程时确定。
- 访商寻藏：第二段可先取货栈物资，第三段可采买，第四段在交锋和休整间选择。
- 连破强敌：中间三段均可选择强敌，以更多粮耗和风险换取辎重。

页面可提前查看五段节点；启程后路线和待选战法固定，刷新不会改变。护送行旅带来的商摊优惠、首领援助，以及搜索遗货引来的追兵继续生效。

每趟最多一种备战，保存计划不扣资源，启程时一次付清，途中不能更改：

| 备战 | 条件及额外成本 | 本趟收益 |
| --- | --- | --- |
| 轻装出行 | 无额外成本 | 无额外加成 |
| 修制路标 | 伐木场 2 级；木材 20、碎银 30 | 每场战斗粮耗额外减少 20%，最终向上取整 |
| 随军医囊 | 医馆 2 级；草药 3、布匹 2 | 每场胜利后在阵英雄恢复 8% 气血，不复活 |
| 出征合练 | 兵营 2 级；粮草 25、碎银 40 | 每场开战在阵英雄怒气增加最多 10 |

启程粮草和备战粮草一起检查；不足时整个操作回退，不先扣另一项资源。已付备战成本不会因提前收队返还。

## 长期目标：九项契约

「山河 → 江湖留名」展示三地区各三项契约。无新增每日次数、签到或倒计时清零；启程前选择，险途及绝险可接受：

- 全员归寨：英雄全程无人退阵；敌方气血、攻击、防御增加 15%。
- 无药行军：战斗药品和野营药包都未使用；敌方气血、攻击、防御增加 20%。治疗技能、休整和医囊可用。
- 破阵疾行：所有交战耗时合计不超过 60 秒；敌方气血、攻击、防御增加 25%。选择路线会影响总耗时。

完整走通回寨并达标后，每地区每契约首次获得招贤令 1、材料自选匣 2，总计九份首奖。再次达标只更新最高难度与历次最快用时；两项纪录分别取最佳值。普通游历收益和随机奖励照常结算。未达契约仍可领取正常完整通关收益；途中战败或提前收队按原规则处理。

## 必得与随机掉落

原有副本已经实行两类奖励，本版补全材料掉落表。例如景阳冈：

- 胜利结算必得：碎银 420、威望 8、功勋 10、参战好汉每人经验 240，虎骨 2、虎皮 1、经验丹 1、武学残页 3、精制草料 2、驯骑凭记 1。
- 额外独立判定：武松信物 15%、金创药 50%、凡品马料 40%。
- 原有装备搜获仍为 25%；符合条件的坐骑契仍每张独立 20%、无保底，已有契约或已领骑者不重复掉契。

上述概率未修改。江湖游历新增以下额外掉落，完整走通且回寨时每项独立判定，无保底，可能同时出现，也可能全部落空。三个难度的概率和数量相同：

| 路线 | 35% | 20% | 8% |
| --- | --- | --- | --- |
| 青石古道 | 强化符碎片 ×2 | 武学残页 ×3 | 强化符 ×1 |
| 芦荡渡口 | 草药 ×3 | 精制草料 ×2 | 养元丹 ×1 |
| 断崖粮道 | 碎铁 ×3 | 粗布 ×3 | 强化符 ×1 |

完整通关的路契（2 / 3 / 4）、目标物资、暂存收益和原有首次/本期奖励继续必得。随机奖励在这些收益之外，提前收队不判定。结算弹窗「掉落明细」逐项显示获得、未掉落或未判定，契约结果也显示在此页。

随机数沿用本机存档的确定性状态：同一份待结算快照重载后结算相同；已结算不能重复领取。这不是服务端权威防作弊系统。

## 旧存档与发布顺序

旧存档直接使用。更新前已开始的旧版行程不临时增加备战、契约或随机奖励；原战局不补触发新开场本领。完成后新开行程采用本版规则。

**需要更新 Worker；不新增 D1 数据表，不运行 SQL 迁移。** 新能力字段是 `campaignPlans: 1`，覆盖人物本领战局/复盘、出行计划、随机收获和挑战记录。旧云服务会被上传预检拦截，本机存档保留；新版服务拒绝旧页面删掉已有契约或降低完成记录。

Git Bash 中每行单独执行：

```bash
cd /f/nav-main/nav-main
npm ci
npm run test:all
npm run build
npx wrangler deploy --config cloud/shuihu/wrangler.json
curl https://save.baizeone.top/v1/game-version
```

确认云端返回 `release: "0.44.0"`、`campaignPlans: 1`，再更新 GitHub 前端：

```bash
git status
git add public/game cloud/shuihu package.json scripts docs
git diff --cached --stat
git commit -m "feat: add hero roles journey preparation contracts and bonus drops"
git pull --rebase origin main
git push origin main
```

暂存范围包含此前未提交的游戏改动，请核对清单。若 rebase 冲突，解决后 `git add`、`git rebase --continue`，完成后再 push；不要强推。推送后的上线取决于已有部署流程，等待成功再刷新游戏。
