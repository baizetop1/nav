# 学习、发布、多端与阅读：使用及验收说明

2026-09-08 更新。本页描述这次实现，优先于旧文档中的“只读工作台”“仅 Inbox + 打卡同步”“只能创建博客草稿”等阶段性限制。

## 1. 正式完成任务与启用路线

1. 打开 Tech OS → 核心问题，按正文步骤学习并打卡。
2. 页面下方“完成任务 / 启用下一路线”输入 nav 仓库的 Contents 读写 Token，读取最新状态。
3. 填写真实结论、实验记录或产物地址，检查变更列表，确认提交。
4. 系统在单个 Git commit 中把当前 Quest 移到 completed、激活下一 Quest 并修改 state.yml。最后一个 Quest 结束后，当前任务留空并进入路线复盘；不会凭空创建完成证据。
5. 启用新路线：先在路线引擎生成候选并提交到路线储备，再到“路线储备”下方选中它。没有 Quest 的路线需要你填写问句，系统据此建立基础任务模板。
6. 未完成的旧主路线暂停到 graveyard，已完成的旧路线移入 completed。旧任务和记录保留。新主路线及首个任务由你确认后才启用。

读取使用远端最新 branch head；分支变化会停止提交，不 force push。确认提交后工作台即刻更新，公开站点仍需等 Pages 构建。

仓库编辑草稿、任务结论和证据草稿本机自动保存，Token 不保存。仓库读取采用三方比较；双方同时修改同一文件时必须明确选择，刷新不能绕过冲突确认。

已加入仓库的 Capture 草稿，即使刷新后再提交，也会根据已提交 Markdown 中的来源 ID 归档本机记录；归档状态需再通过 Inbox 同步到其他设备。仓库草稿目前只在本机自动保存；跨设备继续编辑正式学习文件前，要先提交并在另一端读取仓库。

## 2. 从 Inbox 正式发表到博客

- Inbox 记录上的“博客草稿 / 正式发表”打开表单。
- 可以继续使用“创建博客草稿”，也可以直接点下方“读取并预览正式文章”。
- 若博客有同名草稿，预览以远端最新正文和元信息为准，防止旧 Inbox 覆盖你在 GitHub 改过的文章。
- 确认公开范围后点“确认公开发表”。系统原子创建 `_posts/YYYY-MM-DD-slug.md`；如果从草稿发布，同一提交移除对应 `_drafts/slug.md`，草稿历史仍能在 Git 中恢复。
- 同名已发布文章、远端变化、权限不足会停止操作。来源 Inbox 仍保留，直接正式发表不会自动删除它。
- 成功后提供文章地址和部署状态入口。首次打开文章可能需等待部署完成，不用再运行本地发布命令。
- 博客 workflow 已改为先生成最新文本索引，再检查内容，避免新增文章因旧索引而部署失败。

发布内容可能公开；不要把密码、Token 或私人信息写入文章或公开 Tech OS 证据。

## 3. 统一多端加密同步

电脑与手机都使用同一个 HTTPS 站点、同一 nav 仓库、同一个加密密码。

1. 有数据的设备：Inbox → 多端加密同步 → 合并并同步。
2. 新设备：同一入口输入 Token 与密码 → 从云端恢复。这一步只有读取，没有 GitHub 提交。
3. 另一设备产生新记录后，再合并同步；回到第一台设备再次恢复或同步。

统一文件仍是 `data/inbox.enc.json`。外层加密格式保持兼容，内部数据升为 v3，读取兼容旧 v1/v2。旧版网页不能写新格式，避免把新增字段删掉；开始使用前两端都应刷新到新版。

同步覆盖：Inbox、归档与删除标记、Tech OS 打卡、导航内容与布局、主题与场景、临时文本、访问统计、临时访问、翻译历史、稍后阅读及阅读位置。

合并规则：

- Inbox 按记录 ID 合并，打卡按任务步骤合并；阅读按文章 URL 合并，保留删除标记。
- 导航设置和各类历史按存储类别采用较新版本；并发修改不会自动拼接正文/导航 JSON，每类保留最近 5 个不同版本供人工恢复。它不是实时多人协同编辑。
- 在 Inbox 的“设置与历史副本”可预览并恢复版本，恢复后需再次同步。
- 请求期间的新本机修改会再次合并；实际未上传的修改仍标为待同步。
- Token 和密码不存储；本机 LocalStorage 仍为明文，只有上传 GitHub 的共享文件加密。

正式 Tech OS Markdown 仍通过仓库入口提交；它不是私有 Inbox。旧单便笺/导航完整备份入口作为兼容入口保留，日常多端使用统一入口即可。

## 4. 手机阅读与图谱

导航首页新增“阅读中心”和“知识图谱”。

- 阅读中心支持最近阅读、稍后阅读、接着读；可粘贴链接或选择博客文章。
- 博客记录本机阅读位置，并显示“继续上次阅读”“稍后阅读”和“阅读中心 / 多端同步”。
- 跨端流程：电脑读文章 → 电脑导航同步 → 手机导航恢复 → 阅读中心继续。隐私窗口和普通窗口存储互不共享，需要分别恢复。
- 仅本站博客可记录位置；外部链接只支持稍后阅读，不读取第三方网页正文。
- 离线时仍可本机记录；同步和公开发布需要网络。此版本不把整个博客抓取成离线镜像。
- 图谱只读公开文本索引，支持主题、节点类型、最近更新与一跳关系筛选，点击节点可打开原文。没有关系的节点会显示为孤立节点，不伪造连接；项目节点要先有公开索引数据。

## 5. 验证与部署

导航：Node 24，`npm ci` 后执行 `npm run verify`（构建 + 所有自检）。

博客：`npm run check`；新增文章时先 `npm run build:text-index`。完整 Jekyll 构建需要本机 Jekyll 或 GitHub Pages workflow。

建议实机验收：

1. 两台设备分别新增 Inbox 记录，往返同步后都能看到两条。
2. 同一任务勾选/取消打卡，往返同步后状态一致；删除 Inbox 后旧设备同步不能复活旧记录。
3. 电脑记录阅读位置，手机恢复后继续；检查稍后阅读和删除记录。
4. 输入错误密码、断网、使用无权限 Token；本机记录不清空。
5. 完成一条 Quest，检查旧路径移除、新路径与 state.yml 在同一 commit。
6. 创建并预览博客草稿，在 GitHub 修改后重新预览，确认发布使用修改后的正文。
7. 仓库草稿编辑后刷新仍存在；远端并发变化会锁定提交。

本地自动化用隔离浏览器和模拟 GitHub API 验证，不会提交测试文章到真实仓库。上线后仍需你用真实设备与 Token 做最后一轮验收。

本次本地验收：导航生产构建及 22 组自检通过；博客内容检查与 9 项文本索引测试通过。隔离的电脑/手机尺寸浏览器已覆盖加密恢复、阅读续接、图谱交互、Quest 原子迁移、博客预览发表，以及仓库草稿刷新与冲突锁定。手机情报栏横向溢出导致底部按钮不可点的问题已修复。完整 Jekyll/Pages 部署和真实设备联网验收尚未在这里执行。

参考：[GitHub Git Trees API](https://docs.github.com/en/rest/git/trees#create-a-tree)，文件移动采用新路径写入和旧路径 `sha: null`，始终指定 base tree 并非强制更新分支。
