# 招贤结果弹窗 · 0.2.1

在招贤馆点击「使用一张招贤令」或「专属招贤」，行动完成后立即弹出结果。招募概率、保底、相识条件、消耗和奖励不变。

| 结果 | 弹窗内容 |
| --- | --- |
| 好汉入寨 | 姓名、称号、星级，说明是否补入出阵队伍；满队时提示到好汉页调整 |
| 故友来访 | 已有好汉不重复增加人数，明确显示对应信物 ×3、功勋 +15 |
| 英雄传闻 | 尚未相识，不会入寨；显示实际好汉、信物 ×2 和寻访地点 |

专属招贤没有抽到目标时，分别说明邀请目标和实际回应者，避免把目标误显示为已获得。

## 交互与保存

- 「知道了」、右上角 ×、Esc 关闭；「查看好汉」关闭后进入好汉页。
- 弹窗不自动关闭。打开时锁住背景交互及滚动，Tab / Shift+Tab 在弹窗按钮内切换。
- 关闭后尽量把焦点还给原招贤按钮。按钮无可用招贤令时不强行聚焦禁用控件。
- 手机小屏和横屏可在弹窗内部滚动，操作按钮至少 44px 高。
- 结果来自当次行动的 `recruit.lastResult`，不重新抽取，也不把同次触发的卷终奖励算成招贤奖励。
- 本机保存成功才显示「已保存」。存储额度不足时明确提示尚未保存，可关闭弹窗到存档页导出内存中的进度。
- 多标签存档冲突会暂停写入；已打开的弹窗保留结果并显示冲突提示。失败或招贤令不足不弹出成功结果。
- 刷新页面不会自动重播上次弹窗或重复发奖。存档格式仍为 version 2，缺少可选结果字段的旧存档仍可读取。
- 游戏模块、CSS 的资源参数统一更新为 0.2.1；不需要清空本机存档。

## 验收

- `npm run test:shuihu-recruit`：普通/专属结果、入寨/满队/重复/未相识/非目标、原状态不变、一次消耗、旧存档兼容、无效字段拒绝、文本转义、卷终奖励隔离。
- `npm run verify`：生产构建及全部 26 组自检。
- 现代 Edge 实际点击检查：连续双击只扣一次、焦点循环/恢复、Esc、查看好汉、刷新不重放、切回页面不消失、缺令/存储额度/多标签冲突。
- 1440px 桌面、320px / 390px 手机尺寸、844×390 横屏检查边界、滚动和按钮可点击性。
