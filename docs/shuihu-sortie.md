# 白泽水浒 0.16.0：出征准备与战后复盘

## 出征准备

寨子清剿、匪患亲征、领地据点、江湖副本、每日材料本和周本都先打开准备页。计策副本也展示入口条件和消耗，但明确不派兵。剧情中的即时遭遇沿用原流程。

准备页使用真实出征逻辑在状态副本上计算，展示实际体力与粮草消耗、出发后余额、实际随军人数、双方属性、兵种克制、副本机制及治疗/打断缺项。展开配置区域可调整三名英雄、带兵或独行、军令和人数，也可采用已保存阵容。更改后先更新预览，确认后才保存配置并扣除消耗。直接确认未更新的配置时会先重算，要求核对新方案。取消不修改原存档、不扣每日次数。

## 战后复盘

结算弹窗增加可展开的本战复盘；梁山志保留最近一场完整结果，刷新、文件导出与云端保存均可保留。

- 每名英雄统计直接伤害、有效治疗、实际承伤、成功施加或刷新眩晕的次数、直接截断首领蓄势次数、主动施招次数。
- 伤害只计实际扣除的气血，治疗排除满血溢出。药品恢复单独列出，不计入英雄治疗。
- 敌方受到的流血/中毒单列总量，不猜测归属；我方承受的地形伤害单列，同时计入对应英雄承伤。
- 保存结局原因、时长、剩余气血和随军伤兵，根据实际退阵、超时、目标失败及施招记录给出调整提示。
- 旧版已经开始的战局保持原规则，不补造缺失统计。报告仅用于玩家复盘，不作为可信竞赛或反作弊凭据。

新增可选 `battle.metrics` 与 `lastBattle`。统计不消费随机数、不改变战斗数值；只保留最近一战以控制存档大小。

## 云端上线

此轮没有新增数据库迁移。需要更新现有 Worker，使 `/v1/game-version` 返回 `reports:1`；旧服务不支持时前端阻止上传含复盘记录的存档，保留本机与文件备份。

在原项目 Git Bash 执行：

```bash
cd /f/nav-main/nav-main
npx wrangler deploy --config cloud/shuihu/wrangler.json
```

静态页面继续通过现有 GitHub 发布流程更新。如果 0.14.0 的演武排名表尚未迁移，仍需先完成其升级说明；本轮不会自动迁移、部署或上传生产存档。

## 验证

全量自检通过；新增检查覆盖六类真实入口、预览只读、配置生效、消耗限制、伤害/气血守恒、有效治疗、直接打断、药品分账、持续伤害、旧战局接续、报告序列化和旧云端阻止上传。隔离浏览器在缺少三个旧手机接口时验证预览取消、无效阵容、预设、整场胜利、手机结算及桌面梁山志，并检查导出与刷新后的复盘保留。
