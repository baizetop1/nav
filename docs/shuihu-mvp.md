# 白泽水浒 · MVP 0.1 验收清单

依据 `kf` 中六份 v1.0 文档实现第一卷《郓城风起》，不是仅实现 TDD 开发顺序中的“页面、存档、数据加载”。

## 范围取舍

- 以总路线图为阶段边界，以内容文档为剧情依据，以数值文档为战斗/招募规则。
- 30 个文字节点覆盖郓城、景阳冈、东溪村、黄泥冈和梁山脚下；保留条件入口、隐藏节点、返回路径。
- 两条主线包含武松打虎、七星聚义、智取生辰纲。玩家只指挥，不代替武松打虎；晁盖、阮小二、阮小五是剧情人物，不占 12 名可招好汉。
- 12 名正式好汉、30 个技能、50 种道具、20 件基础装备、20 个事件、12 种每日任务、5 个历练副本。
- 野猪林、风雪山神庙、祝家庄在 0.1 提供独立的传闻历练，不提前实装第二卷全文及文本迷宫。
- 寨主无战斗等级；好汉 MVP 上限 40，后续再扩至 85。“建立梁山”仅完成初级据点里程碑，建筑升级、坐骑与高级强化留待后续。马厩目前是线索节点，不显示不可用的养成按钮。
- 基础养成包括队伍三人编排、经验培养、装备穿卸、打造、分解与 +0～+5 强化。每日驯马任务保留数据但在未开放坐骑时不派发。
- 普通招贤严格按 1/6/23/45/25% 的五星到一星权重，并有 20/50/100 抽保底；未相识的核心人物不会直接入寨，招贤只带来线索/信物，需完成相识。专属 25/5/70%，四次未得目标后下一次必得目标。无付费功能。
- 独立键 `baize_shuihu_save`；不读写 Inbox、学习数据、GitHub Token。存档仅在当前浏览器，不声称自动跨端同步；提供校验后的手动导入/导出和备份恢复。

## 交付与验收

- 静态页面：`public/game/index.html`，随导航构建部署到 `/nav/game/`；相对资源路径也支持单独静态托管。
- 页面：江湖、好汉、行囊、招贤、差事、梁山志、存档。全中文、手机可用、键盘可操作、无外部资源和后端依赖。
- 验证：JSON 字段/引用/数量；普通招贤 100000 次模拟、保底与重复英雄；主线真实流程、黄泥冈失败重试；战斗状态/技能/道具/撤退；跨日刷新/体力；存档版本/坏档/并发标签页；浏览器桌面/手机、刷新接续战斗与导入导出。
- 第一卷完成：两条主线、三名正式好汉、十次历练、威望 150，落脚初级梁山并出现第二卷传闻。

完整养成的周节奏属于可调平衡目标，不等于上线后已做过一周真实用户测试。

## 如何开始玩

1. 打开白泽导航，在首页工具栏点击「白泽水浒」；也可按 `Ctrl/Cmd + K` 搜索「白泽水浒」。游戏会另开标签页，保留原导航页面。
2. 点击「进入郓城县」，先去县衙看榜文，再去酒肆结识白胜、时迁、打听传闻。与白胜交谈后可以请他同行，首支队伍不需要抽卡。
3. 郓城城门 → 官道 → 景阳冈 → 酒家，结识武松、循虎踪进入深林。剧情战由武松临时参战，注意每回合提示，在猛扑时防守、空隙时进攻、伏低时用计。
4. 回到城门前往东溪村，完成七星聚义，再到黄泥冈执行计策。黄泥冈关注警觉、疲劳、信任与暴露，不只靠攻击。
5. 在「差事」领取任务奖励；到招贤馆招募、在「好汉」编排三人队和培养等级、到铁匠铺打造与强化装备。「梁山志」可回看经历与卷终条件。

副本入口：景阳冈（1 级）、黄泥冈（10 级，主线完成后重游）、梁山脚下的「历练渡口」（野猪林 20 级、山神庙 30 级、祝家庄 40 级）。后三处还需完成生辰纲主线。每处每日限三次，撤退也计入次数。

第一卷完成需要：景阳冈主线完成、生辰纲主线完成、至少三名正式好汉、十次历练胜利、威望 150。满足后自动建立初级梁山，并显示第二卷传闻；不是通关一次景阳冈就完成整个 MVP。

## 本地运行与部署

在 Git Bash 中运行：

```bash
cd /f/nav-main/nav-main
npm run dev
```

打开终端给出的本地地址，再从导航进入游戏；也可在该地址下访问 `/nav/game/`。首次安装项目且没有 `node_modules` 时，先执行 `npm ci`。不要双击 `public/game/index.html` 用 `file://` 打开：模块与 JSON 加载需要 HTTP 服务。

现有 `npm run build` 会把 `public/game` 原样放进导航构建产物，沿用现有 GitHub Pages 部署流程；部署后入口是 `https://baizeone.top/nav/game/`。游戏不依赖后端、付费接口或在线素材。本次本地实现没有代替用户提交或推送 GitHub。

导航的 Service Worker 已单独排除游戏路径，避免把游戏 HTML 缓存成导航首页。老浏览器标签页需刷新、接收新的 Service Worker 后再进入。

## 存档与数据维护

- 每次有效操作自动保存到当前浏览器的 `baize_shuihu_save`，上一份有效内容保存在 `baize_shuihu_save_backup`。
- 换设备时，在「存档」导出 JSON 文件，再到另一台设备导入并确认。HTTP、HTTPS、不同域名和浏览器的存储互不相通；清除站点数据前应导出。
- 多标签页发生存档冲突时会阻止旧标签页覆盖，请重新载入最新存档。空间不足时保留内存进度并提示导出；损坏存档不会被自动清空。
- 角色、地图、剧情、任务、物品等内容位于 `public/game/data/`。`schema.json` 描述以各文件名为键合并的数据结构；`js/data.js` 另做跨文件 ID 和规则校验。
- 单独验收游戏：`npm run test:shuihu`；全项目构建与回归：`npm run verify`。
