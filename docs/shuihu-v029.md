# 白泽水浒 0.29.0 · 军需、战役与云端协作

## 入口与兼容

行囊可查看补给、分类与加工配方；山河中的「军需与战役」开启组合技、专属任务、寨防、接力及势力抉择。对应好汉详情也可直接进入专属任务。云端协作在存档页。

旧档保留六卷、112 位人物、培养、资源及战斗。新系统使用可选扩展字段，开启不会重置进度；已开始的旧战斗不追溯加入新战法。本轮新增 6 种道具，总道具数 482；人物数不变。专属实战任务先覆盖林冲、花荣、阮小七三人，组合技先做三组。

## 2. 组合技与个人实战

组合成员共同取胜三次解锁。合击要求所有成员在阵且存活、未受眩晕、各有怒气 20；触发时每人扣除 20。每战最多两次，间隔至少 15 秒，会影响个人技能释放时机。

- 二龙山聚义：鲁智深、武松、杨志；队伍已有承伤后触发。
- 阮氏连舟：阮小二、阮小五、阮小七；水战触发。
- 钩枪引弓：花荣、徐宁；敌人破甲或首领蓄力时触发。

专属任务要求本人 10 级、聚义厅 2 级；三项共用每日三次尝试额度。每次体力 10、粮草 5 加随军人数一半向上取整，使用真实战斗和兵损。首次达标获本人招式书 2、灵蕴 2及永久本领强化。

- 林冲「枪阵护乡」：本人参战、至少带兵 50、全员存活取胜；本人新战斗开场获得 8 秒 4% 护阵。
- 花荣「校场破旗」：本人独行，60 秒内取胜；普通攻击伤害 +5%。
- 阮小七「水泊接应」：本人参战、至少带兵 100、水战全员存活取胜；水战防御 +5%。

## 3. 三波寨防与三队接力

两种战役各每日一次，要求聚义厅 3 级。开始消耗体力 15、粮草 20；寨防另需木材 40、碎银 80。每场再付粮草 5 加实际兵力五分之一向上取整。

寨防四选一：加固寨门（防御 +12%）、箭楼齐射（敌方起始气血降低 8%）、山道陷阱（敌速降低 15%）、预备救护（胜利后存活者恢复 10% 气血）。三波沿用同一阵容和剩余气血，已退阵者不复活，真实兵损不回滚。玩家主动开始，离线不会遭到袭击；本版采用布防方案选择。

接力分前哨、水路、主寨三场，每场 1—3 人；本轮已经出场的人不能再用。通过出征准备调整新队伍、带兵和军令。

每胜一场暂存碎银 100、精铁 2，完成三场返回领取全部及自选箱 1；提前收队或战败带回暂存物资的一半。资源已消耗与阵亡不会撤销。支持战斗暂停、保存和刷新接续。

## 4. 势力抉择

郓城、景阳、东溪各每月选择一次；聚义厅 1、2、3 级依次开放。商会：碎银 100 换粮草 60；乡村：粮草 40 换药草 5；船帮：木材 30 换粗布 3。支持方关系 +12，另外两方各 −4，下限为 0。

支持当地势力时，本月当地委托战全队起始怒气 +5。选择立即生效，当月不可改选；下月可重新选择。

## 5. 云端协作讨伐

沿用每月四期，按服务器东八区时间结算日期。现有 20 个云端槽位共同累积贡献；聚义厅 3 级、已编队、结束当前战斗和远征的云档可以参与。每档每天两次，服务器使用已上传阵容重新演算，每次贡献最多 2000。不消耗或修改该云档的游戏物资。重复请求不会重复扣次数。

| 全服本期累计贡献 | 每个本期已有正贡献存档可领一次 |
| --- | --- |
| 3000 | 军需自选箱 1 |
| 10000 | 养元丹 1 |
| 20000 | 军需自选箱 1、招贤令 1 |

公开页面只展示存档编号和贡献。领奖需要此档密钥，奖励与领取记录原子写入云端；领取后须下载、比较并接续，才会进入本机进度。旧本机进度直接覆盖刚领奖的云档会被阻止。

领取账本独立于游戏快照：回滚到领奖前不会允许重新领取，也不会自动补发回滚掉的奖励。服务器复算战斗用于核实贡献，但培养数据仍来自上传存档，并非完全防作弊系统。

## 6. 发布顺序与详细命令

本次必须新增数据库表。对已运行的数据库，只执行 0003 迁移，不用重新初始化 schema.sql，也不用重复执行此前已安装的 0002。0003 使用 CREATE TABLE IF NOT EXISTS，可重复执行，不覆盖现有存档。

以下在项目根目录的 Git Bash 中逐行执行，每步成功后再执行下一步。不要把 pull 和 push 拼成一条命令。

先本地检查：

~~~bash
cd /f/nav-main/nav-main
npm run test:all
npm run build
~~~

再更新数据库，然后部署 Worker：

~~~bash
npx wrangler d1 execute baize-shuihu-saves --remote --file cloud/shuihu/migrations/0003_cooperative.sql --config cloud/shuihu/wrangler.json
npx wrangler deploy --config cloud/shuihu/wrangler.json
~~~

迁移后可只读确认，结果应有两张表：

~~~bash
npx wrangler d1 execute baize-shuihu-saves --remote --command "SELECT name FROM sqlite_master WHERE type='table' AND name IN ('cooperative_attempts','cooperative_claims');" --config cloud/shuihu/wrangler.json
~~~

然后提交并推送前端与配套代码：

~~~bash
git status
git add public/game cloud/shuihu package.json scripts/shuihu-selfcheck.mjs scripts/shuihu-v029-selfcheck.mjs docs/shuihu-v029.md
git diff --cached --stat
git commit -m "更新水浒 0.29：军需补给、战役与云端协作"
git pull --rebase origin main
git push origin main
~~~

如果 rebase 提示冲突，先解决冲突并完成 rebase，再 push；不要强制推送。GitHub 上传成功后，前端仍需由原有部署流程完成发布；已连接仓库自动部署时查看构建结果。仅更新 GitHub 不会替代上面的 D1 迁移和 Worker 部署。

若本地提示 tsc 找不到，先停止正在运行的本地开发服务，在项目根目录执行 npm ci --include=dev，再重新检查和构建。
